Query Aggregation Roadmap

A single, evidence-led map of what Privacy Router must implement, what it should clean up, what belongs to research, and what should not be built.

The key truth

Query Aggregation is not a naming exercise. It is the fail-closed boundary that prevents an extractor failure, contradictory record set, or local-model outage from becoming an external raw-prompt leak.

9 P0 packages · 3 P1 packages · 7 P2 packages · 2 research packages · 10 explicit exclusions

The smallest correct runtime change

Keep the design boring and inspectable. One explicit artifact moves through deterministic boundaries; span evidence remains separate from the query-level decision.

Problem — span evidence exists, but the query-level decision is implicit inside Judge, so the fail-closed invariant is hard to verify at each boundary.

  1. Explicit extraction outcome
    success | failed(reason)
  2. Pure query summary
    ExtractionResult → QueryDecisionSummary
  3. Deterministic policy
    Judge(summary) → canonical action
  4. Invariant-enforcing route
    Router(summary, action) → allowed endpoint
  5. Atomic masking contract
    ExtractionRecord[] → MaskingContract
  6. Single-extraction proxy
    one request → one evidence set
  7. Observable boundary tests
    unsafe state → 0 external raw calls

Design constraint: a stateful QueryAggregator class is optional. The required abstraction is a schema plus one pure aggregation function. Do not add a package or service until state or dependency injection makes it necessary.

P0 · Security and correctness

These packages close the actual raw-transmission risk. They are ordered by dependency and each ends in an externally observable contract.

P0.1Lock the external-transmission invariant in testsRequired

Problem

The current suite does not prove that extractor exceptions, invalid structured output, contradictory records, or local failures produce zero external raw calls.

Required change

Write adapter-spy acceptance tests before changing runtime behavior. Cover safe, maskable, essential, mixed, parse failure, schema failure, invalid offsets, invalid mask indices, local failure, and hydration failure.

Affected paths

  • agents/extractor/tests/
  • agents/judge/tests/
  • agents/router/tests/
  • tests/core/test_masker.py
  • server/tests/

Acceptance

A test named for extraction failure observes exactly zero external raw calls. Every unsafe branch asserts both the route decision and the trust-boundary payload.

P0.2Distinguish extraction success from failureRequired

Problem

A successful zero-record extraction and a failed extraction can collapse into the same is_sensitive=false, records=[] state. Downstream code can misread uncertainty as safety.

Required change

Add an explicit failure status and normalized failure reason to ExtractionResult. Invalid records must never disappear silently into a safe result.

Affected paths

  • agents/extractor/schemas.py
  • agents/extractor/extractor_core.py
  • agents/extractor/extractor.py
  • agents/extractor/__init__.py

Acceptance

Successful empty extraction has extraction_failed=false; any call, parse, schema, or record-validation failure has extraction_failed=true and cannot become allow.

P0.3Add QueryDecisionSummary and pure aggregationRequired

Problem

Extractor, Judge, Router, and MiddleMan can each derive their own partial aggregate from span records, allowing counts, essentiality, and maskability to drift.

Required change

Define QueryDecisionSummary and one pure summarize_extraction() function. Keep ExtractionRecord[] as the masking and audit source of truth.

Required fields

  • Failure state and reason
  • Sensitivity, essentiality, and maskability
  • Record and essential counts
  • Category counts and ordered categories
  • Validated mask indices

Acceptance

Pure unit tests cover empty, maskable, essential, mixed, duplicate-category, and failure inputs with deterministic output. No database table or stateful service is introduced.

P0.4Make Judge consume the summaryRequired

Problem

Judge currently accepts loose dictionaries and can reconstruct a different state from the one used by masking or routing.

Required change

Make the rule-based Judge consume QueryDecisionSummary and emit only allow, selective_mask, block, or prompt_user.

Affected paths

  • agents/judge/judge.py
  • agents/judge/schemas.py
  • agents/judge/tests/test_judge.py

Acceptance

Failure never maps to allow; non-essential-only maps to selective_mask; any essential record maps to block. New code emits no legacy alias.

P0.5Enforce final Router invariantsRequired

Problem

The Router can translate a policy string into an endpoint without checking whether the action contradicts extraction failure, essential records, or an empty masking set.

Required change

Validate the summary-action pair at the final execution boundary. Normalize legacy aliases only at ingress; keep internal and output vocabulary canonical.

Affected paths

  • agents/router/schemas.py
  • agents/router/router.py
  • agents/router/tests/test_router.py

Acceptance

allow requires successful extraction with zero records. selective_mask requires validated non-empty records and no essential span. Contradictions fail before an adapter call.

P0.6Close MiddleMan and forced-override bypassesRequired

Problem

MiddleMan can recalculate policy after user record overrides and forced generation can be confused with audited, request-scoped user consent.

Required change

Reuse the same summary, Judge, and Router path after every override. Until explicit consent has a separate authenticated contract, essential or failed extraction remains blocked or prompts the user.

Affected paths

  • agents/router/middle_man.py
  • server/mcp/tools.py
  • router and MCP tests

Acceptance

Deleting records or forcing generation cannot convert an essential or failed request into an external raw route. Record indices and post-override summaries are validated.

P0.7Make masking atomic and hydration fail-fastRequired

Problem

A missing span or invalid index can be skipped, leaving raw text in a partially masked payload. Hydration validation does not currently enforce the documented unknown-placeholder failure.

Required change

Validate every index, offset, span, category, and placeholder before replacement. Either produce the complete contract or fail the whole masking operation. Reject unknown placeholders during hydration.

Affected paths

  • agents/masker/masker.py
  • agents/masker/schemas.py
  • agents/masker/errors.py
  • tests/core/test_masker.py

Acceptance

One invalid record aborts the batch; no external call follows. Known placeholders round-trip exactly, while any placeholder outside the contract produces a typed hydration failure.

P0.8Apply single-extraction in the API proxyRequired

Problem

The proxy can extract once for policy and again for masking. Different results create a time-of-check/time-of-use gap. Local failures or streaming can also downgrade to an external masked route.

Required change

Generate one extraction, summary, record set, and masking contract per request. Reuse them through policy, masking, forwarding, and hydration. Local failure must not change the trust decision.

Affected paths

  • server/api/routes/proxy.py
  • server/api/routes/responses.py
  • server/tests/

Acceptance

The Extractor is called exactly once. Essential, failed, or invalid requests never downgrade to external forwarding. Hydration failure never returns a partial success response.

P0.9Constrain API and MCP metadataRequired

Problem

Response metadata can copy raw spans, full extraction records, or placeholder maps into client logs and downstream telemetry even when forwarding itself is safe.

Required change

Default to counts, categories, actions, routes, and redacted placeholder identifiers. Put raw detail behind an explicit authenticated local-only contract if it remains necessary. Align TypeScript types with the actual wire payload.

Affected paths

  • server/api/routes/
  • server/mcp/tools.py
  • web/src/lib/types/api.ts
  • web/src/lib/types/index.ts

Acceptance

Ordinary API and MCP logs contain no raw spans or restoration values. Payload fixtures match frontend types exactly, and target-only fields are not represented as current runtime fields.

P1 · Release consistency

These packages do not change policy, but they determine whether someone else can install, run, and verify the product described by the repository.

P1.1Split production and experiment dependenciesRelease

Why

The core API calls OpenAI-compatible endpoints and should not require GPU engines or optimization packages to install.

Change

Separate core, experiment, local-inference, and document-generation dependency groups. Keep engine-specific packages opt-in.

Acceptance

A CPU-only core installation and API image succeed without vLLM, Optuna, or Ninja.

P1.2Reconcile Docker and Hermes execution contractsRelease

Why

Compose comments, README instructions, profile expectations, and CI smoke tests describe different default service sets.

Change

Choose one default, align every command, pin the Hermes source revision, separate core and Hermes smoke gates, and remove stale integration references.

Acceptance

One documented command always starts the same service set and both core and optional Hermes paths have reproducible smoke checks.

P1.3Separate deterministic tests, integration tests, and real-LLM evalRelease

Why

Pure unit tests, database tests, running-server scenarios, and model-quality evaluation currently have overlapping collection and documentation.

Change

Define explicit markers and commands for unit, integration, scenario, and real-LLM evaluation. Make CI and README use the same commands.

Acceptance

The deterministic suite passes without Docker or network access; service and model gates run only when explicitly requested.

Explicitly excluded

Removing unjustified work is part of the roadmap. These items either duplicate existing boundaries, contradict project decisions, or add no observable safety.

  • ×
    Create a speculative core/ package

    The summary schema and pure function fit the existing Extractor/Router boundary. Add a package only after a real ownership or cycle problem appears.

  • ×
    Revive an LLM-based Judge

    Reasoning belongs in extraction; policy and route selection stay deterministic and testable.

  • ×
    Add observability in this change

    Telemetry is a separate future concern and must not steer the fail-closed design.

  • ×
    Duplicate local inference inside Privacy Router

    The router consumes OpenAI-compatible endpoints. Engine-specific inference stays in model services and configuration.

  • ×
    Do not evaluate SGLang executability or compatibility

    SGLang executability and compatibility are outside this roadmap and will not be evaluated.

  • ×
    Delete archives unconditionally

    Historical experiments carry provenance. Retention requires an explicit size, licensing, or privacy policy.

  • ×
    Recreate deprecated tests

    Test current behavior and current interfaces rather than restoring files mentioned by stale audits.

  • ×
    Reimplement the web documentation system

    The route tree, renderer, locale stores, and navigation already exist. Repair truthfulness and parity instead.

  • ×
    Add LICENSE, Mermaid, or retired integrations

    These conflict with explicit project decisions and do not support this safety change.

  • ×
    Treat commit squashing as product functionality

    Compact history is integration hygiene, not a runtime deliverable or security claim.

Recommended execution order

Each step earns the next. Documentation truthfulness comes first; experimental breadth comes last.

  1. Label Query Aggregation as target architectureStop presenting the planned component as current behavior.
  2. Write fail-closed acceptance testsObserve the current raw-transmission weakness before implementation.
  3. Add explicit extraction failureSeparate safe empty output from unknown output.
  4. Add the pure query summaryCompute one deterministic decision artifact.
  5. Wire Judge to the summaryEmit canonical policy actions only.
  6. Enforce Router invariantsReject contradictory action-state pairs before execution.
  7. Close override bypassesRecompute through the same path and keep forced generation fail-closed.
  8. Make masking and hydration atomicOne invalid record aborts the complete operation.
  9. Apply single-extraction in the proxyReuse one evidence set and remove external downgrade.
  10. Constrain API and MCP metadataKeep raw evidence out of ordinary downstream logs.
  11. Run deterministic focused testsProve trust-boundary behavior without model or network variability.
  12. Repair docs, localization, and accessibilityMake the verified behavior understandable to both locales.
  13. Reconcile packaging, Compose, and CIMake the release reproducible by another operator.
  14. Run real-LLM evaluation separatelyMeasure model quality after deterministic correctness is stable.

Query Aggregation 작업 지도

Privacy Router가 반드시 구현할 일, 릴리스 전에 정리할 일, 연구로 분리할 일, 그리고 만들지 말아야 할 일을 하나의 근거 중심 문서로 정리했습니다.

핵심 결론

Query Aggregation은 이름을 추가하는 작업이 아닙니다. Extractor 실패, 모순된 record 집합, local model 장애가 외부 raw prompt 유출로 바뀌지 않도록 만드는 fail-closed 경계입니다.

가장 작은 올바른 런타임 변경

설계는 단순하고 검증 가능해야 합니다. 하나의 명시적 artifact가 결정 경계를 통과하고, span 증거는 query-level 판단과 분리된 상태로 유지됩니다.

문제 — span 증거는 있지만 query-level 결정이 Judge 내부에 암묵적으로 섞여 있어, fail-closed invariant를 각 경계에서 검증하기 어렵습니다.

  1. 명시적 추출 결과
    success | failed(reason)
  2. 순수 query summary
    ExtractionResult → QueryDecisionSummary
  3. 결정론적 policy
    Judge(summary) → canonical action
  4. Invariant를 검증하는 route
    Router(summary, action) → allowed endpoint
  5. Atomic masking contract
    ExtractionRecord[] → MaskingContract
  6. Single-extraction proxy
    one request → one evidence set
  7. 관찰 가능한 경계 테스트
    unsafe state → external raw call 0회

설계 제약: stateful QueryAggregator class는 선택 사항입니다. 필수 abstraction은 schema와 하나의 순수 집계 함수입니다. 상태나 dependency injection이 실제로 필요해질 때까지 새 package나 service를 추가하지 않습니다.

우선순위 지도

지금까지 언급된 모든 작업이 release blocker는 아닙니다. Trust boundary 정확성, 릴리스 정합성, 문서 품질, 모델 엔진 연구를 구분합니다.

P0 · 보안과 정확성

실제 raw 전송 위험을 닫는 작업입니다. 의존 순서대로 배치했으며, 각 작업은 외부에서 관찰 가능한 계약으로 끝납니다.

P0.1외부 전송 invariant를 테스트로 고정필수

문제

현재 suite는 Extractor 예외, 잘못된 structured output, 모순된 record, local 장애가 외부 raw call 0회를 만든다는 사실을 증명하지 않습니다.

필요한 변경

런타임을 바꾸기 전에 adapter spy 기반 acceptance test를 작성합니다. Safe, maskable, essential, mixed, parse 실패, schema 실패, invalid offset/index, local 실패, hydration 실패를 포함합니다.

대상 경로

  • agents/extractor/tests/
  • agents/judge/tests/
  • agents/router/tests/
  • tests/core/test_masker.py
  • server/tests/

완료 기준

Extraction 실패 테스트에서 external raw call이 정확히 0회입니다. 모든 unsafe branch가 route label뿐 아니라 trust-boundary payload도 검증합니다.

P0.2Extraction 성공과 실패를 구분필수

문제

정상적인 zero-record 추출과 실패한 추출이 같은 is_sensitive=false, records=[] 상태로 합쳐질 수 있습니다. Downstream이 불확실성을 안전으로 오해합니다.

필요한 변경

ExtractionResult에 명시적 실패 상태와 정규화된 실패 이유를 추가합니다. Invalid record를 조용히 삭제해 safe 결과로 만들면 안 됩니다.

대상 경로

  • agents/extractor/schemas.py
  • agents/extractor/extractor_core.py
  • agents/extractor/extractor.py
  • agents/extractor/__init__.py

완료 기준

정상 empty extraction은 extraction_failed=false, call·parse·schema·record 검증 실패는 extraction_failed=true이며 allow가 될 수 없습니다.

P0.3QueryDecisionSummary와 순수 집계 구현필수

문제

Extractor, Judge, Router, MiddleMan이 span record에서 각각 부분 집계를 만들면 count, essentiality, maskability가 서로 달라질 수 있습니다.

필요한 변경

QueryDecisionSummary와 하나의 순수 summarize_extraction() 함수를 정의합니다. ExtractionRecord[]는 masking과 audit의 source of truth로 유지합니다.

필수 필드

  • 실패 상태와 이유
  • 민감도, 필수성, maskability
  • 전체 record와 essential count
  • Category count와 결정론적 category 순서
  • 검증된 mask index

완료 기준

순수 unit test가 empty, maskable, essential, mixed, duplicate category, failure를 결정론적으로 검증합니다. DB table이나 stateful service는 추가하지 않습니다.

P0.4Judge가 summary만 사용필수

문제

Judge가 loose dictionary를 받아 masking이나 routing과 다른 상태를 다시 만들 수 있습니다.

필요한 변경

Rule-based Judge는 QueryDecisionSummary를 입력받고 allow, selective_mask, block, prompt_user만 출력합니다.

대상 경로

  • agents/judge/judge.py
  • agents/judge/schemas.py
  • agents/judge/tests/test_judge.py

완료 기준

Failure는 allow가 될 수 없습니다. Non-essential only는 selective_mask, essential 하나 이상은 block입니다. 새 코드는 legacy alias를 출력하지 않습니다.

P0.5Router 최종 invariant 적용필수

문제

Router가 policy string을 endpoint로 바꾸면서 extraction failure, essential record, empty mask set과 action의 모순을 확인하지 않을 수 있습니다.

필요한 변경

최종 실행 경계에서 summary-action 조합을 검증합니다. Legacy alias는 ingress에서만 정규화하고 내부와 출력은 canonical vocabulary를 사용합니다.

대상 경로

  • agents/router/schemas.py
  • agents/router/router.py
  • agents/router/tests/test_router.py

완료 기준

allow는 성공한 zero-record extraction만 허용합니다. selective_mask는 essential이 없는 검증된 nonempty record가 필요합니다. 모순은 adapter 호출 전에 실패합니다.

P0.6MiddleMan·forced override 우회 차단필수

문제

MiddleMan이 user override 이후 policy를 별도로 재계산할 수 있고, forced generation이 감사 가능한 request-scoped user consent와 혼동될 수 있습니다.

필요한 변경

모든 override 이후 같은 summary, Judge, Router 경로를 재사용합니다. 명시적 consent가 별도 authenticated contract를 갖기 전까지 essential 또는 failed extraction은 block 또는 prompt 상태를 유지합니다.

대상 경로

  • agents/router/middle_man.py
  • server/mcp/tools.py
  • router and MCP tests

완료 기준

Record 삭제나 forced generation으로 essential 또는 failed request가 external raw route가 되지 않습니다. Record index와 post-override summary를 검증합니다.

P0.7Masking atomic·Hydration fail-fast필수

문제

찾지 못한 span이나 invalid index를 건너뛰면 raw text가 일부 남은 payload가 외부로 전송될 수 있습니다. Hydration validation도 문서화된 unknown-placeholder 실패를 강제하지 않습니다.

필요한 변경

치환 전에 모든 index, offset, span, category, placeholder를 검증합니다. 완전한 contract를 만들거나 전체 masking을 실패시킵니다. Hydration 중 unknown placeholder를 거부합니다.

대상 경로

  • agents/masker/masker.py
  • agents/masker/schemas.py
  • agents/masker/errors.py
  • tests/core/test_masker.py

완료 기준

하나의 invalid record가 전체 batch를 중단하고 external call은 발생하지 않습니다. Known placeholder는 정확히 round-trip하고 contract 외 placeholder는 typed hydration failure를 만듭니다.

P0.8API proxy single-extraction 적용필수

문제

Proxy가 policy 결정을 위해 한 번, masking을 위해 다시 추출하면 서로 다른 결과로 TOCTOU gap이 생깁니다. Local 실패나 streaming이 external masked route로 downgrade될 수도 있습니다.

필요한 변경

Request마다 하나의 extraction, summary, record set, masking contract를 만들고 policy, masking, forwarding, hydration에서 재사용합니다. Local 실패는 trust decision을 바꾸지 않습니다.

대상 경로

  • server/api/routes/proxy.py
  • server/api/routes/responses.py
  • server/tests/

완료 기준

Extractor 호출은 정확히 1회입니다. Essential, failed, invalid request가 external로 downgrade되지 않습니다. Hydration 실패를 partial success로 반환하지 않습니다.

P0.9API·MCP metadata 경계 정리필수

문제

Response metadata가 raw span, 전체 extraction record, placeholder map을 client log와 downstream telemetry로 복사할 수 있습니다.

필요한 변경

기본값은 count, category, action, route, redacted placeholder identifier만 제공합니다. Raw detail이 필요하면 명시적인 authenticated local-only contract로 분리합니다. TypeScript type을 실제 wire payload와 맞춥니다.

대상 경로

  • server/api/routes/
  • server/mcp/tools.py
  • web/src/lib/types/api.ts
  • web/src/lib/types/index.ts

완료 기준

일반 API와 MCP log에 raw span 또는 restoration value가 없습니다. Payload fixture와 frontend type이 정확히 일치하며 target-only field를 현재 runtime field처럼 표현하지 않습니다.

P1 · 릴리스 정합성

Policy를 바꾸지는 않지만, 다른 사람이 repository 설명대로 설치하고 실행하고 검증할 수 있는지를 결정합니다.

P1.1제품·실험 dependency 분리릴리스

이유

Core API는 OpenAI-compatible endpoint를 호출하므로 설치 과정에서 GPU engine이나 optimization package가 필수가 아니어야 합니다.

변경

Core, experiment, local inference, document generation dependency group을 분리하고 engine package는 opt-in으로 유지합니다.

완료 기준

CPU-only core 설치와 API image가 vLLM, Optuna, Ninja 없이 성공합니다.

P1.2Docker·Hermes 실행 계약 정리릴리스

이유

Compose 주석, README, profile 기대값, CI smoke가 서로 다른 기본 service 집합을 설명합니다.

변경

하나의 default를 선택해 모든 명령을 맞추고, Hermes source revision을 고정하고, core와 Hermes smoke gate를 분리하고, 오래된 integration 참조를 제거합니다.

완료 기준

문서화된 하나의 명령은 언제나 같은 service 집합을 시작하며 core와 optional Hermes 경로 모두 재현 가능한 smoke check가 있습니다.

P1.3테스트·평가 경계 분리릴리스

이유

Pure unit, DB, running-server scenario, model-quality eval의 collection과 문서가 겹쳐 있습니다.

변경

Unit, integration, scenario, real-LLM eval용 marker와 명령을 명시하고 CI와 README가 같은 명령을 사용하게 합니다.

완료 기준

Deterministic suite는 Docker와 network 없이 통과하고 service/model gate는 명시적으로 요청할 때만 실행됩니다.

P2 · 문서와 UX

시스템을 이해 가능하게 만드는 작업입니다. 첫 작업은 즉시 필요합니다. 계획된 보안 동작을 현재 runtime 사실처럼 표현하면 안 됩니다.

P2.1현재·목표 설계 구분품질

변경

Extractor → Judge → Router를 현재로, Extractor → Query Aggregation → Judge → Router를 runtime과 test가 증명될 때까지 목표로 표시합니다.

완료 기준

모든 planned schema와 component에 Target 또는 미구현 상태가 보입니다.

P2.2현재 상태 페이지 추가품질

변경

Blocker, 구현 상태, 결정 필요 항목, 연구 제약, accepted risk, resolved history를 문제·영향·근거·완료 기준으로 정리합니다.

완료 기준

독자가 과거 audit 문장을 해석하지 않고 다음 release blocker를 찾을 수 있습니다.

P2.3README 정합성 수정품질

변경

문서 route 이름, source document 경로, model/runtime 주장, Docker service 의미, test 명령을 수정합니다.

완료 기준

README의 모든 public URL과 명령이 실제 build와 runtime에서 동작합니다.

P2.4완전한 영문·한국어 제공품질

변경

모든 heading, 설명, table, control, scenario, status label, download label을 완전한 locale surface로 옮깁니다.

완료 기준

언어 전환이 전체 읽기 경험을 바꾸며 기술 identifier는 유지하되 prose는 언어를 섞지 않습니다.

P2.5Source·web 문서 parity 보장품질

변경

Build-time link rewrite가 있는 단일 source of truth를 선택하거나 synchronized web copy가 달라질 때 실패하는 parity test를 추가합니다.

완료 기준

문서 하나를 수정하고 public copy를 잊으면 deterministic test가 실패합니다.

P2.6Audit·TODO 역사 분류품질

변경

Audit를 날짜가 있는 snapshot으로 표시하고 backlog를 done, active, deferred, decision-needed, rejected, historical로 분류합니다.

완료 기준

해결된 경로와 과거 요청이 현재 blocker처럼 보이지 않습니다.

P2.7접근성 경고 제거품질

변경

Label association, accessible name, menu state, modal semantic과 focus, keyboard click equivalent, deprecated slot 사용을 수정합니다.

완료 기준

Svelte check가 error 0개, accessibility warning 0개를 보고하고 keyboard-only navigation이 모든 interactive path를 포함합니다.

연구 전용 작업

엔진 coverage와 근거를 강화하지만 OpenAI-compatible core API release를 막지는 않습니다.

R.1모델별 vLLM 매트릭스 작성보류

범위

Model, engine version, image, architecture, response format, memory, startup, 반복 평가 결과를 기록합니다.

완료 신호

Compatibility를 generic하게 주장하지 않고 model/version별로 기록합니다. Monkey patch는 product-critical 조합과 pinned upstream behavior가 있을 때만 허용합니다.

R.2실험 결과 manifest 정합화보류

범위

Authoritative manifest를 선택하고 모든 결과를 valid, partial, archived, contaminated, pending으로 분류합니다.

완료 신호

Historical result와 current result가 구분되고 manifest가 완료된 output을 pending으로 표시하지 않습니다.

명시적으로 제외할 일

근거 없는 작업을 제거하는 것도 roadmap의 일부입니다. 다음 항목은 기존 경계를 중복하거나 프로젝트 결정을 위반하거나 관찰 가능한 보안을 추가하지 않습니다.

  • ×
    추측으로 core/ package 만들기

    Summary schema와 순수 함수는 기존 Extractor/Router 경계에 둘 수 있습니다. 실제 ownership 또는 cycle 문제가 생길 때만 package를 추가합니다.

  • ×
    LLM Judge 부활

    Reasoning은 extraction에 두고 policy와 route 선택은 deterministic하고 testable하게 유지합니다.

  • ×
    이번 변경에 observability 추가

    Telemetry는 별도 future concern이며 fail-closed 설계를 이끌면 안 됩니다.

  • ×
    Privacy Router 내부에 local inference 중복 구현

    Router는 OpenAI-compatible endpoint를 사용합니다. Engine-specific inference는 model service와 config에 남깁니다.

  • ×
    SGLang 실행 가능성·호환성 평가 제외

    SGLang 실행 가능성과 호환성은 이 로드맵에서 평가하지 않습니다.

  • ×
    Archive를 조건 없이 삭제

    Historical experiment는 provenance를 갖습니다. Retention에는 size, licensing, privacy 정책이 필요합니다.

  • ×
    Deprecated test를 복구

    오래된 audit에 나온 파일을 복원하지 말고 현재 behavior와 interface를 test합니다.

  • ×
    Web documentation system 재구현

    Route tree, renderer, locale store, navigation이 이미 있습니다. Truthfulness와 parity를 고칩니다.

  • ×
    LICENSE, Mermaid, retired integration 추가

    명시적 project decision과 충돌하고 이번 safety change를 지원하지 않습니다.

  • ×
    Commit squash를 제품 기능으로 취급

    Compact history는 integration hygiene이지 runtime deliverable이나 security claim이 아닙니다.

권장 실행 순서

각 단계가 다음 단계를 정당화합니다. 문서의 정직함을 먼저 확보하고 실험 범위 확장은 마지막에 둡니다.

  1. Query Aggregation을 목표 설계로 표시계획된 component를 현재 behavior처럼 보여주지 않습니다.
  2. Fail-closed acceptance test 작성구현 전에 현재 raw transmission 약점을 관찰합니다.
  3. 명시적 extraction failure 추가Safe empty output과 unknown output을 분리합니다.
  4. 순수 query summary 추가하나의 결정론적 decision artifact를 계산합니다.
  5. Judge를 summary에 연결Canonical policy action만 출력합니다.
  6. Router invariant 적용실행 전에 모순된 action-state 조합을 거부합니다.
  7. Override 우회 경로 차단같은 경로에서 다시 계산하고 forced generation도 fail-closed로 유지합니다.
  8. Masking과 hydration atomic 적용하나의 invalid record가 전체 작업을 중단합니다.
  9. Proxy에 single-extraction 적용하나의 evidence set을 재사용하고 external downgrade를 제거합니다.
  10. API와 MCP metadata 제한일반 downstream log에 raw evidence를 남기지 않습니다.
  11. Focused deterministic test 실행Model과 network 변동 없이 trust-boundary behavior를 증명합니다.
  12. 문서, locale, 접근성 정리검증된 behavior를 두 언어로 이해 가능하게 만듭니다.
  13. Packaging, Compose, CI 정리다른 운영자가 release를 재현할 수 있게 합니다.
  14. Real-LLM eval 별도 실행Deterministic correctness가 안정된 뒤 model quality를 측정합니다.

완료 기준

Route label만으로는 증거가 되지 않습니다. 완료 여부는 external adapter와 trust boundary를 통과하는 payload에서 측정합니다.
