# 소크라틱 민감도 탐지 프레임워크 (Detection Framework)

Privacy Router의 **Extractor(추출기)**가 동작하는 핵심 원리와 탐지 가이드라인입니다. 단순 키워드 매칭이 아닌 소크라틱 질문 체인을 통해 AI가 민감성의 근거를 문맥적으로 추론하고 카테고리를 동적으로 유도합니다.

---

## 1. 핵심 원칙

> **"이 정보에 기밀 가치가 조금이라도 있다면 탐지하고 마스킹한다."**

일반적인 개념이나 고유명사라도 민감한 문맥(미공개 연구, 내부 사업 의사결정 등)에 위치해 있다면 적극적으로 민감 스팬으로 식별합니다.

---

## 2. 소크라틱 질문 체인 (Socratic Chain)

추출기는 각 문장에 대해 다음 3단계 질문을 순서대로 적용합니다:

### 질문 1: 신원 노출 (Identity Exposure)
> *"이 정보로 특정 개인을 식별할 수 있는가?"*
- 주민등록번호, 전화번호, 이메일, 여권번호, 성명+소속 조합 등.
- 민감 정보 자체를 직접 묻는 표현도 포함 ("주민번호가 뭐야?" 등).

### 질문 2: 경쟁적 해악 (Competitive Harm)
> *"이 정보가 외부에 공개될 경우 경쟁사에게 유익하거나 기업에 손해를 주는가?"*
- 미공개 연구(아이디어, 방법론, 비공개 데이터, 진행 상태).
- 내부 사업 결정, 전략 근거, 제조 로드맵.
- 심각도 기준: **방법론(HOW) > 아이디어(WHAT) > 진행 상태(STATUS)**.

### 질문 3: 개인적 해악 (Personal Harm)
> *"이 정보가 노출되면 당사자에게 실질적인 금전적/보안상 피해가 발생하는가?"*
- API 키, 비밀번호, 사내 인트라넷 URL, 급여, 프로젝트 예산 등.

---

## 3. 동적 카테고리 유도 (Dynamic Category Derivation)

고정된 분류 체계에 의존하지 않고, 문맥에 따라 가장 적절한 `SCREAMING_SNAKE_CASE` 카테고리명을 생성합니다:

1. **핵심 속성**: 이 정보가 가진 가장 본질적인 특성은 무엇인가?
2. **민감 이유**: 노출 시 어떤 피해가 발생하는가?
3. **명명 규칙**: 위 판단을 바탕으로 구체적인 영문 스네이크 케이스로 명명합니다.

| 텍스트 스팬 | 본질 및 피해 | 유도된 카테고리명 |
|---|---|---|
| `901212-1234567` | 개인 고유 식별 번호 (신원 노출) | `RESIDENT_REGISTRATION_NUMBER` |
| `김동현` | 개인 실명 (신원 노출) | `PERSON_NAME` |
| `Contextual Distillation` | 미공개 연구 핵심 개념 (경쟁 우위 상실) | `UNPUBLISHED_RESEARCH_CONCEPT` |
| `TSMC 3nm 공정 채택` | 제조 공정 결정 (기술/사업 기밀) | `FABRICATION_PROCESS_DECISION` |
| `850억원` | 사내 프로젝트 예산 (재정 기밀) | `PROJECT_BUDGET_AMOUNT` |
| `sk-or-v1-...` | API 인증 키 (시스템 무단 접근) | `API_CREDENTIAL` |

---

## 4. 스팬 추출 최소 단위 규칙 (Span Rules)

스팬(`span`)은 민감 정보의 **실체 엔티티만** 포함해야 하며, 한국어 조사나 문법적 수식어는 엄격히 제외합니다.

- **포함 대상**: 고유명사, 수치/금액, 기술 용어, 식별자.
- **제외 대상**: 조사(은/는/이/가/을/를/에/에서), 수식어(새로운, 높은), 동사 어미(결정했다, 재학 중인).

### 분리 및 정제 예시

| 원문 | ✅ 올바른 추출 스팬 | ❌ 잘못된 추출 스팬 |
|---|---|---|
| "광주과학기술원에 재학 중인 김동현" | `["광주과학기술원", "김동현"]` | `["광주과학기술원에 재학 중인 김동현"]` |
| "TSMC 3nm 공정 채택 결정" | `["TSMC 3nm 공정"]` | `["TSMC 3nm 공정 채택 결정"]` |
| "홍길동, 김철수, 이영희" | `["홍길동", "김철수", "이영희"]` | `["홍길동, 김철수, 이영희"]` |

---

## 5. 필수성 판정 (Masking Test: `is_essential`)

각 스팬에 대해 마스킹 가능 여부를 검증합니다:

> *"이 스팬을 플레이스홀더(`CATEGORY#hash`)로 가려도, 사용자의 본래 요청 의도가 유지되는가?"*

| 판정 결과 | `is_essential` | 설명 | 조치 방향 |
|---|---|---|---|
| **의미 유지됨** | `false` | 민감 정보가 요청의 '재료/배경'인 경우 | 마스킹 후 외부 모델 호출 (`selective_mask`) |
| **의미 손실됨** | `true` | 민감 정보 자체가 요청의 '질문 목적/핵심 주제'인 경우 | 로컬 온디바이스 모델에서만 처리 (`block`) |

### `is_essential` 비교 예시

- **배경 정보 (`is_essential: false`)**:
  - *"주민번호 901212-1234567을 포함해서 확인 이메일 양식 작성해줘"* $\rightarrow$ 마스킹 후 이메일 양식 생성 가능.
  - *"삼성전자 AP 개발 건으로 TSMC 3nm 채택한 내용 보고서로 정리해줘"* $\rightarrow$ 마스킹 후 보고서 골격 작성 가능.
- **핵심 질문 (`is_essential: true`)**:
  - *"내 주민번호가 뭐야?"* $\rightarrow$ 마스킹하면 `[MASKED]가 뭐야?`가 되어 질문 자체가 성립하지 않음.
  - *"Attention을 대체할 새로운 아이디어 구상안에 대해 평가해줘"* $\rightarrow$ 아이디어 자체가 핵심 가치이므로 외부 전송 불가.

---

## 6. 고정밀 추출 (Critic 검토)

`Extractor(precision="high")` 옵션을 활성화하면 1차 추출 후 **Critic**이 교차 검토를 수행하여 미세하거나 복합적인 민감 스팬의 누락을 2차 보완합니다.

---

## 7. 추출 출력 데이터 규격

```json
{
  "sensitivity": {
    "is_sensitive": true,
    "rationale": "식별 가능한 개인정보 및 내부 사업 의사결정이 포함되어 있습니다."
  },
  "records": [
    {
      "category": "RESIDENT_REGISTRATION_NUMBER",
      "span": "901212-1234567",
      "confidence": 0.98,
      "reasoning": "개인을 고유하게 식별하는 국가 등록 식별자입니다.",
      "is_essential": false
    }
  ]
}
```
