# 정보 추출·기밀 여부·필요 여부와 권장 행동

Privacy Router의 **Extractor(추출기)**는 공개·비공개 정보를 항목별로 추출하고, 기밀 여부와 작업 필요 여부를 독립적으로 판단한다. 각 판단에는 이유가 포함되며 근거가 부족하면 해당 판단만 별도 미판정 상태로 남긴다.

---

## 1. 핵심 원칙

> **"공개 정보도 설명하되, private 또는 기밀 여부 미판정인 정보는 보호한다."**

일반적인 개념이나 고유명사라도 민감한 문맥(미공개 연구, 내부 사업 의사결정 등)에 위치해 있다면 적극적으로 민감 스팬으로 식별합니다.

---

## 2. 문맥 기반 민감성 판단

추출 프롬프트는 다음 관점에서 입력 전체의 민감 정보를 검토합니다:

### 질문 1: 신원 노출 (Identity Exposure)
> *"이 정보로 특정 개인을 식별할 수 있는가?"*
- 주민등록번호, 전화번호, 이메일, 여권번호, 성명+소속 조합 등.
- 민감 정보 자체를 직접 묻는 표현도 포함 ("주민번호가 뭐야?" 등).

### 질문 2: 경쟁적 해악 (Competitive Harm)
> *"이 정보가 외부에 공개될 경우 경쟁사에게 유익하거나 기업에 손해를 주는가?"*
- 미공개 연구(아이디어, 방법론, 비공개 데이터, 진행 상태).
- 내부 사업 결정, 전략 근거, 제조 로드맵.
- 심각도 기준: **방법론(HOW) > 아이디어(WHAT) > 진행 상태(STATUS)**.

### 질문 3: 개인적 해악 (Personal Harm)
> *"이 정보가 노출되면 당사자에게 실질적인 금전적/보안상 피해가 발생하는가?"*
- API 키, 비밀번호, 사내 인트라넷 URL, 급여, 프로젝트 예산 등.

---

## 3. 동적 카테고리 유도 (Dynamic Category Derivation)

고정된 분류 체계에 의존하지 않고, 문맥에 따라 가장 적절한 `SCREAMING_SNAKE_CASE` 카테고리명을 생성합니다:

1. **핵심 속성**: 이 정보가 가진 가장 본질적인 특성은 무엇인가?
2. **민감 이유**: 노출 시 어떤 피해가 발생하는가?
3. **명명 규칙**: 위 판단을 바탕으로 구체적인 영문 스네이크 케이스로 명명합니다.

| 텍스트 스팬 | 본질 및 피해 | 유도된 카테고리명 |
|---|---|---|
| `901212-1234567` | 개인 고유 식별 번호 (신원 노출) | `RESIDENT_REGISTRATION_NUMBER` |
| `김동현` | 개인 실명 (신원 노출) | `PERSON_NAME` |
| `Contextual Distillation` | 미공개 연구 핵심 개념 (경쟁 우위 상실) | `UNPUBLISHED_RESEARCH_CONCEPT` |
| `TSMC 3nm 공정 채택` | 제조 공정 결정 (기술/사업 기밀) | `FABRICATION_PROCESS_DECISION` |
| `850억원` | 사내 프로젝트 예산 (재정 기밀) | `PROJECT_BUDGET_AMOUNT` |
| `sk-or-v1-...` | API 인증 키 (시스템 무단 접근) | `API_CREDENTIAL` |

## 4. 스팬 추출 최소 단위 규칙 (Span Rules)

스팬(`span`)은 공개·비공개 정보의 **실체나 작업에 의미 있는 값의 최소 단위**를 포함한다. 공개 주제·설정·매개변수도 반환하되 모든 조사나 접속어를 별도 항목으로 만들지 않는다.

- **포함 대상**: 고유명사, 수치/금액, 기술 용어, 식별자.
- **제외 대상**: 조사(은/는/이/가/을/를/에/에서), 수식어(새로운, 높은), 동사 어미(결정했다, 재학 중인).

### 분리 및 정제 예시

| 원문 | ✅ 올바른 추출 스팬 | ❌ 잘못된 추출 스팬 |
|---|---|---|
| "광주과학기술원에 재학 중인 김동현" | `["광주과학기술원", "김동현"]` | `["광주과학기술원에 재학 중인 김동현"]` |
| "TSMC 3nm 공정 채택 결정" | `["TSMC 3nm 공정"]` | `["TSMC 3nm 공정 채택 결정"]` |
| "홍길동, 김철수, 이영희" | `["홍길동", "김철수", "이영희"]` | `["홍길동, 김철수, 이영희"]` |

## 5. 항목별 기밀 여부와 필요 여부

각 `ExtractionRecord`는 다음 두 객체를 제공한다. 둘 다 `value`, `reason`, 계산된 `status`를 가진다.

| 판단 | 이진 값 | 의미 |
|---|---|---|
| `confidentiality` | `public` / `private` | 해당 정보가 공개 가능한 정보인지, 비공개로 보호할 정보인지 |
| `necessity` | `required` / `optional` | 해당 특정 원래 값이 명시된 작업의 완료 조건에 필요한지 |

판정한 객체의 `status`는 `assessed`다. 근거가 부족하면 `status="unassessed"`, `value=null`이며 `reason`에 무엇이 부족한지 설명한다. 미판정은 세 번째 분류 라벨이 아니고 public·optional이라는 뜻도 아니다. 새 모델 출력에는 미판정인 경우까지 **두 이유가 모두 필수**다. `status`는 모델이 별도로 추측하지 않고 값에서 계산하므로 모순되는 상태를 만들지 않는다.

공개된 기술 주제가 작업에 필요하면 `public + required`, 비공개 수신 주소가 일반 문구 초안에는 불필요하면 `private + optional`이 가능하다. 기밀 여부와 필요 여부를 서로 추론하지 않는다. 의도가 없거나 원문과 충돌하면 필요성은 미판정으로 남지만 원문에 근거한 기밀 판정은 계속한다.

`ExtractionResult.masking_preserves_task`는 **분석 원문 전체의 private·기밀 미판정 값을 함께 가리고 public 정보와 작업 지시는 유지했을 때** 완료 조건을 유지하는지 같은 호출에서 별도로 판단한다. `True`는 유지, `False`는 완료 불가, `None`은 근거 부족이며 `masking_reason`에 이유를 기록한다. 여러 대화에 걸친 작업이면 전체 대화를 분석 원문에 포함해야 한다.

채널 미정으로 각 연락처의 필요성이 미판정이어도 모든 연락처가 사라지면 전달 불가라는 전체 판단은 가능하다. 반대로 작업 자체가 없거나 초안·실제 발송을 구별하지 못하면 전체 영향은 미판정이다. 모든 값이 optional이라는 것만으로 공동 마스킹의 안전을 추론하지 않으며 나중의 복원이나 다른 실행기가 원문을 가진다고 가정하지 않는다.

`HeuristicPolicy.recommend(session_results)`는 추가 모델 호출 없이 다음 우선순위를 적용한다.

1. 근거 없음·실패·부분 결과·보호 필요성이 있지만 위치 없는 결과는 보류한다.
2. 기밀 여부 미판정인 항목이 있으면 `confidentiality_unassessed` 사유로 보류한다.
3. private 항목이 required이거나 전체 마스킹이 작업을 막으면 `keep_local`이다.
4. 그 외 private 값의 전체 마스킹 영향이 미판정이면 보류하고, 작업 유지가 확인되면 `mask_then_share`다. 개별 필요성만 미판정이면 전체 판단을 사용할 수 있다.
5. public 항목만 있는 완전한 결과는 필요성과 무관하게 `share_original`이다.

권장 행동은 세 가지이며 보류는 `action=None`으로 외부 전달을 차단한다. 항목별 분류·실행 상태·행동 권고는 별개다. 자동 판정에는 오류가 있을 수 있으며 public 판정이나 권고가 전송 권한을 부여하지 않는다.

## 6. 의도 분석과 단일 패스 추출

`Annotator`의 계약은 `annotate(text: str) -> IntentAnnotation`이다. `IntentAnalyzer(Annotator)`는 신뢰된 로컬 모델에서 의도 내용을 분석하고, 모델 밖에서 정확한 원문의 UTF-8 SHA-256(`source_hash`)에 결합한다. 어노테이션은 변경 불가능하며 `goal`, `action`, `completion_condition`, 선택적 `channel`, 미해결 사항의 tuple인 `unresolved`를 제공한다.

```python
from agents import Extractor, IntentAnalyzer

text = "synthetic@example.invalid로 보낼 안내문 초안만 작성해줘. 실제 발송하지 마."
intent = IntentAnalyzer().annotate(text)
result = Extractor().extract(text, intent=intent)
```

의도를 이미 아는 상위 에이전트는 `IntentAnnotation.for_text(...)`로 직접 제공할 수 있다. Extractor는 원문을 그대로 유지하고 어노테이션은 별도 근거로 전달한다. 다른 원문에 결합된 어노테이션은 호출 전에 거부하며, 원문과의 호환성이 확인되지 않으면 개별 필수성과 전체 마스킹 판단을 모두 `None`으로 남긴다. 민감 레코드를 검증하지 못해 누락시킨 경우에도 전체 마스킹의 안전성을 주장하지 않는다. 어노테이션에 실행·공개 권한을 부여하지 않는다.

공개 항목을 포함해 어떤 모델 항목이든 원문 위치·값 검증에서 탈락하면 결과의 `status`는 `partial`이다. Policy는 이를 공개 판정으로 바꾸지 않고 보류하며 Cachier는 저장하지 않고 동일 키의 이전 결과도 제거한다.

의도 분석기의 분석·파싱·JSON 출력 작업은 사용자의 목표가 아니다. 원문과 이전 문맥에 수행 요청이 없다면 작업을 만들어내지 않으며, 구체적인 요청 확인이 필요함을 남긴다. 반대로 실제 요청의 채널·일정만 미정인 경우를 작업 자체의 부재로 바꾸지 않는다.

`Extractor().extract(text)`처럼 의도를 생략해도 공개·비공개 정보를 추출하지만 필요성은 미판정이다. 한 번의 추출 호출에서 항목별 두 판단·두 이유·전체 마스킹 영향을 함께 반환한다. `IntentAnalyzer`를 사용하는 흐름은 의도 분석과 추출의 두 단계이며 캐시·Policy는 LLM을 호출하지 않는다. 동일 의도로 캐시에 적중하면 두 단계를 건너뛸 수 있다.

의도 입력 계약은 `ExtractorCore`, `Extractor`, `agents.extractor.extract()`에 적용된다. 정규화 탐지기도 새 항목별 판단 객체를 사용하지만, PII 전용 탐지기는 자신이 검출한 항목을 private으로 설명하고 작업 필요성은 미판정으로 남긴다. 의도 분석 실패는 `IntentAnalysisUnavailable`, 추출 실패는 `PrivacyAnalysisUnavailable`이며 공개 판정으로 바꾸지 않는다.

`PrivacyRouter`를 사용하면 의도 분석부터 마스킹·복원까지 실행하면서 `on_status` 콜백으로 실제 단계별 시작·완료·건너뜀·실패를 받는다. 검사가 완료됐다는 실행 상태와 권장 행동은 서로 다르며, 완료된 검사에서도 전체 마스킹 영향을 판단할 근거가 부족하면 행동을 보류한다. 모델 호출 실패는 `RoutingError`와 실패 이벤트로 전달된다. 이벤트에는 민감 원문이나 모델 설명이 없으며, 세부 계약은 [README의 라우터 사용법](../../README.md#라우터-사용과-실행-상태-전파)이 기준이다.

## 7. 추출 출력 데이터 규격

아래는 반환 계약의 구조 예시다. 모델 응답의 `records`는 명시적으로 제공해야 하며 빈 배열은 허용하지만 필드가 없으면 분석 실패다. 분석 내용이 누락된 모델 응답을 공개 판정으로 바꾸지 않는다.

```json
{
  "status": "complete",
  "sensitivity": {
    "is_sensitive": true,
    "rationale": "식별 가능한 개인정보 및 내부 사업 의사결정이 포함되어 있습니다."
  },
  "masking_preserves_task": null,
  "masking_reason": "작업 의도가 제공되지 않아 전체 마스킹 영향을 판정하지 않음",
  "records": [
    {
      "category": "RESIDENT_REGISTRATION_NUMBER",
      "span": "901212-1234567",
      "confidence": 0.98,
      "confidentiality": {"value": "private", "status": "assessed", "reason": "개인을 고유하게 식별하는 국가 등록 식별자입니다."},
      "start": 0,
      "end": 14,
      "necessity": {"value": null, "status": "unassessed", "reason": "작업 의도가 제공되지 않아 필요성을 판정하지 않음"}
    }
  ]
}
```

## 변경 이력

- 2026-09-17: 공개 항목도 추출하고 항목마다 public/private와 required/optional 및 각각의 이유를 반환하도록 변경했다. 미판정은 별도 상태로 유지하며 public+required를 마스킹·로컬 처리의 근거로 사용하지 않는다.
- 2026-09-17: 사용자 승인에 따라 개별 필수성과 원문 전체의 공동 마스킹 영향을 분리했다. 채널 미정과 마스킹 영향 미판정을 구분하고, 추가 모델 호출 없이 전체 판단을 캐시·Policy·Router로 전달한다.
- 2026-09-17: 정보 등급을 폐지하고 `recommend()`의 세 행동과 미판정 시 보류로 전환했다. 추상 Router·실제 단계 이벤트와 행동 권고의 의미를 분리했다.
- 2026-09-17: 사용자 결정에 따라 `Annotator`·`IntentAnalyzer`와 별도 의도 입력을 도입했다. 초안 작성과 실제 실행을 구분하고, 의도 부재·충돌·채널 미정은 필수성 미판정으로 남긴다. 원문 결합과 의도별 캐시 분리 규칙을 반영했다.
- 2026-09-15: peer Gemma 비교에서 추가 탐지가 없었던 결과와 사용자 결정에 따라 Critic과 정밀도 옵션을 제거했다. 단일 패스 Extractor 사용법으로 갱신했다.
- 2026-09-12: 실제 `is_required.value` 삼상태 계약과 추가 LLM 없는 세션 Policy 규칙을 반영했다. 고정밀 옵션 이름만으로 품질 향상을 주장하지 않도록 Critic 설명을 수정했다.
