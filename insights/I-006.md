## Removed Models (with evidence)

### Qwen3.5-9B
- **Accuracy**: 13.3% (87/120 wrong)
- **Errors**: 99/120 (82.5%)
- **Root cause**: Mamba architecture incompatible with vLLM V2 runner. V1 runner produces poor results.
- **Throughput**: 0.18/s (slowest)

### Qwen3-4B
- **Accuracy**: 45.8% (65/120 wrong)
- **Errors**: 26/120 (21.7%)
- **Root cause**: `<think>` reasoning blocks + bare JSON output. Parser handles most but 21.7% still fail.
- **Throughput**: 0.51/s (slow)

## Model Selection Recommendations

| Use Case | Model | Rationale |
|---|---|---|
| **Highest accuracy** | Gemma-12B | 74.2% overall, 68.5% contextual |
| **Balanced (accuracy + speed)** | E4B | 71.7% accuracy, 4.77/s throughput |
| **Highest throughput** | E2B | 62.5% accuracy, 10.15/s |
| **Resource-constrained** | EXAONE-1.2B | 2.4 GiB, 10.07/s (but 51.7% acc) |

## Key Findings
1. **Model size ≠ accuracy**: Gemma-12B (22 GiB) > Gemma-26B (48 GiB) in accuracy
2. **Errors matter more than throughput**: Qwen3-4B has 0.51/s but 26 errors = unusable
3. **LegalCiteBench is secondary**: cat1/cat2 always 0%, cat3 ~60% across all — not decisive
4. **gpu_utilization=0.48**: 40% memory free, all models fit comfortably
