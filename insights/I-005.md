# I-005: Full Model Sweep Analysis

## Summary
10개 모델 전체 스윕 완료. Granite-8B가 90% accuracy로 최고, EXAONE-1.2B가 4.90/s로 최고 throughput.

## Key Insights

### 1. Accuracy Rankings
| Rank | Model | Accuracy | Throughput |
|---|---|---|---|
| 1 | **Granite-8B** | **90.0%** | 0.69/s |
| 2 | EXAONE-1.2B | 80.0% | 4.90/s |
| 3 | E2B | 65.0% | 4.63/s |
| 4 | E4B/Gemma-26B/Gemma-12B | 60.0% | varies |

### 2. Accuracy vs Size — 비선형
- Granite-8B (16.4 GiB) > EXAONE-1.2B (2.4 GiB) > E2B (9.6 GiB)
- 모델 크기가 accuracy를 결정하지 않음
- Granite의 높은 accuracy는 모델 아키텍처/training 품질 때문

### 3. Throughput vs Size — 예측 가능
- 작은 모델 = 높은 throughput (EXAONE 4.9/s > E2B 4.6/s > E4B 2.8/s > 26B 1.2/s)
- Forward pass 속도가 throughput의 주요 결정因素

### 4. JSON Parsing 호환성
| 모델 | 출력 형식 | 파싱 방법 |
|---|---|---|
| Gemma | 순수 JSON | `json.loads()` 직접 |
| Granite | ` ```json {...} ``` ` | 코드 블록 stripping |
| EXAONE | ` ```json {...} ``` ` | 코드 브록 stripping |
| Qwen | `` + bare JSON | think 제거 + brace 추출 |

### 5. vLLM 호환성 이슈
- **Qwen3.5/3.6**: Mamba 아키텍처 → V2 runner 미지원, V1에서 느림
- **Ministral-3B**: Pixtral 멀티모달 아키텍처 → text-only runner 없음
- **Granite-8B**: FlashInfer JIT에 `ninja` 필요 → venv PATH에 추가

### 6. 최적 모델 선택

| 용도 | 추천 모델 | 이유 |
|---|---|---|
| **최고 accuracy** | Granite-8B | 90% acc, 0.69/s |
| **최고 throughput** | EXAONE-1.2B | 80% acc, 4.90/s |
| **균형 (대형)** | E4B | 60% acc, 2.82/s |
| **균형 (소형)** | E2B | 65% acc, 4.63/s |

## Methodology Lessons
1. **모든 캐시된 모델을 조사** — 파일 존재만으로 호환성 판단 불가
2. **코드 블록/추론 텍스트 처리 필수** — Gemma 외 모든 모델이 비표준 출력
3. **에러 원인을 먼저 조사** — ninja 누락, Pixtral 호환 등 환경 이슈가 많음
4. **점진적 저장** — 모델별로 결과 저장하여 중단 시 데이터 보존
