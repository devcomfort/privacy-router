# Review Summary

**Run:** 2026-07-22\
**Subject:** Privacy Router research direction and evaluation plan\
**Final reviewer verdict:** **GO_TO_PILOT**, 8/10\
**Important:** This is approval to run a validity pilot, not approval to produce the full benchmark or claim results.

## Round 0 — Positioning Review

**Score:** 7/10, revise.

Main finding:

- Privacy Router's extractor–masker–router architecture overlaps with PAPILLON, Need to Know, PRISM-style routing, and contemporary privacy-agent work.
- The defensible contribution is a benchmark and empirical study, not a new privacy mechanism.
- The narrow gap is organizational/research confidentiality under lifecycle-status changes, EN/KO controlled pairs, exact spans, and policy actions.
- A PII-only or generic “context-aware privacy” claim is not novel enough.

## Round 1 — Methods Review

**Score:** 6/10, revise.

Blocking findings and applied revisions:

| Finding | Revision |
|---|---|
| `public-or-authorized` conflated disclosure and authorization | Separated disclosure, recipient authorization, purpose authorization, raw-value necessity, route |
| Universal gold action was normative and partly tautological | Introduced frozen policy profile $P_0$, canonical action, and acceptable-action set |
| Counterfactual/causal wording was too strong | Reframed as authored controlled-intervention sensitivity |
| Dataset counts were inconsistent | Defined semantic scenario → variant → language → paraphrase → execution → repetition hierarchy; 2,600–2,800 item envelope |
| Gold metadata could leak into model input | Physically separated `model_input` and `gold`; evaluator rejects mixed requests |
| Character-only leakage missed paraphrases/derived facts | Added exact, literal, information-atom, derived, recipient-specific, and placeholder-side-channel layers |
| Routing changed the downstream model and confounded utility | Split transformation-only and full-system estimands; added route-matched/oracle-route controls |
| C1/C3 statistics were underspecified | Frozen-condition cluster CI for C1; intersection–union leakage superiority + utility non-inferiority for C3 |
| Bilingual pairs could measure translation artifacts | Split translated/independently authored items; shared-threshold primary; naturalness/equivalence validation |
| Resource estimates omitted hierarchy and extra calls | Recalculated 2,600–2,800 items, 300–500 person-hours, critic/generation calls, spending gate |

## Round 2 — Final Methods Review

**Score:** 8/10.\
**Verdict:** **GO_TO_PILOT**.

Resolved well enough for a pilot:

- honest benchmark/reference-system positioning
- separated policy ontology at the conceptual level
- controlled-intervention rather than causal claims
- consistent scenario hierarchy
- model-view/gold separation
- layered semantic leakage
- transformation versus full-system utility
- scenario-cluster statistics
- bilingual validity controls

## Remaining blockers before full benchmark production

1. Implement a total deterministic $P_0$ with closed action vocabulary, precedence, acceptable-action generation, severity, and tests.
2. Fix event/span/atom cardinality for mixed multi-span payloads and deterministic aggregation.
3. Freeze one C3 primary leakage endpoint and fully operationalize atom/derived leakage.
4. Complete artifact-level novelty verification, including licenses, code, venue status, contextual integrity, DLP, and declassification literature.
5. Freeze C1/C3 method, comparator, threshold, denominator, estimator, and ask/deny/timeout handling.
6. Separate candidate spans, contextually protected spans/atoms, unauthorized exposure, and event-level actions.
7. Define trusted gateway inputs for recipient, purpose, authorization, route, and policy semantics.
8. Pass label-specific and subgroup-specific annotation gates; aggregate agreement is insufficient.
9. Freeze ask-user responder, information, turn, timeout, authorization-change, and completion protocol.
10. Reconcile controlled/naturalistic/calibration/detector/E5 counts in one non-overlap manifest.
11. Complete cluster-aware power analysis and pilot-based budget/hardware feasibility checks.
12. Pass known-answer evaluator tests before producing a sealed test set.

## Venue Assessment

- **Best fit:** ACL/EMNLP Findings, if released as a rigorous bilingual evaluation/resource paper with strong same-backbone and contextual baselines.
- **Possible:** PETS, only with stronger threat/policy semantics, semantic leakage, practitioner validity, and a clear privacy-versus-organizational-confidentiality distinction.
- **Not currently justified:** USENIX Security or IEEE S&P; the current plan lacks a new security guarantee or sufficiently broad deployment study.

## Final Position

Proceed only with WP0 and the 80–120-item validity pilot. Do not start full benchmark production, preregister confirmatory claims, or describe the direction as novel until G0/G1 and the remaining policy/schema gates pass.
