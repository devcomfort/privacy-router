# Research Proposal

## Beyond PII: Controlled-Intervention Evaluation of Context-Dependent Confidential Data Control at LLM-Agent Egress

> Korean working title: **PII를 넘어: LLM 에이전트 외부 전송 시점의 맥락 의존 기밀정보 통제에 대한 통제 개입 평가**

**Status:** revised research direction; policy/novelty pilot required before full benchmark production\
**Target artifact:** bilingual benchmark + empirical system paper\
**Reference system:** Privacy Router\
**Date:** 2026-07-22

---

## 1. 핵심 결론

현재 Privacy Router 자체를 새로운 프라이버시 메커니즘으로 주장하면 최근 연구와 겹친다. 특히 PAPILLON은 로컬/클라우드 분기, Need to Know는 task-essential span과 query rewriting, ToolPrivacyBench는 recipient/purpose 기반 tool privacy를 이미 다룬다.

따라서 논문의 중심 기여는 **라우터 알고리즘**이 아니라 다음의 평가 문제로 좁힌다.

> 동일한 문자열도 공개 상태, 수신자 승인, 사용 목적 승인, 과업 필요성에 따라 외부 전송 가능 여부가 달라진다. 최근 benchmark에 대한 예비 감사는 이 요인들을 조직·연구 기밀에서 독립적으로 분리 측정하는 자료가 부족함을 시사한다. 이를 확인한 뒤 EN/KO controlled-intervention benchmark를 만들고 탐지–마스킹–라우팅 파이프라인을 end-to-end로 평가한다.

Privacy Router는 이 benchmark를 실증하는 **reference implementation**이다. 새 암호기법, 새 학습 알고리즘, 새 privacy definition을 주장하지 않는다.

## 2. English Abstract

LLM agents routinely send user and workspace context to model and tool providers. Our preliminary audit suggests that current evaluations emphasize personal data or task-level privacy, while organizational and research confidentiality can depend on lifecycle state, recipient authorization, purpose authorization, and raw-value necessity rather than on a stable data type. We propose a bilingual English–Korean benchmark built from authored controlled-intervention groups in which the same candidate span is evaluated under validated changes to one policy factor. The benchmark separates factual context labels from actions derived under a frozen policy profile and measures exact and proposition-level leakage, span extraction, policy compliance, abstention, downstream task utility, latency, and cost. Privacy Router serves as a reference implementation. The primary scientific question is whether context-aware control improves recall on non-PII organizational and research secrets at a preselected safe-input false-positive operating point while preserving task utility against a strong privacy-aware baseline. This is an evaluation and empirical systems contribution, not a novel privacy primitive or a claim of real-world causal identification.

## 3. 문제 정의

### 3.1 분석 단위

분석 단위는 **후보 외부 전송 결정(candidate egress decision)** 이다. 외부 전송 직전 payload를 검사하지만 결과 action은 local execution일 수 있다. 이벤트는 다음을 포함한다.

- 현재 사용자 요청과 필요한 대화 문맥
- 전송 예정 payload와 canonical serialized form
- intended recipient identity, trust boundary, transport
- declared purpose와 적용할 policy profile
- 공개 상태·수신자 승인·목적 승인을 판단할 수 있는 관찰 가능한 문맥

### 3.2 입력, 사실 label, 정책 action

모델 입력 $x=(c,p,r,u,P)$:

- $c$: conversation/workspace context
- $p$: outbound payload
- $r$: intended recipient와 trust boundary
- $u$: declared purpose or task
- $P$: frozen policy profile identifier

Gold-only annotation은 모델 입력과 물리적으로 분리한다. 각 span $s_i$에는 다음 사실 label을 부여한다.

- `source_path`, `start`, `end`, `span`: source field와 문자 단위 경계
- `information_family`: personal / organizational / research / credential-security
- `disclosure_state`: confidential / public / unknown
- `recipient_authorization`: allowed / disallowed / unknown
- `purpose_authorization`: allowed / disallowed / unknown
- `raw_value_necessity`: required / placeholder_sufficient / irrelevant / unknown
- `owner_or_subject`: person / organization / research group / system
- `information_atoms`: paraphrase·요약·derived leakage를 판정할 명제 단위

Action은 annotator의 독립적인 도덕 판단이 아니라 frozen policy profile $P_0$가 사실 label에서 산출한다. Primary score는 $P_0$ compliance이며, 여러 방법이 안전할 때 `acceptable_actions` 집합을 사용한다.

| 조건 | $P_0$ canonical action | 허용 가능한 대안 |
|---|---|---|
| 관련 상태·승인·필요성이 unknown | ask | deny |
| public, purpose allowed | allow requested route | minimize |
| confidential, recipient/purpose allowed | minimize or allow approved route | local |
| confidential, external unauthorized, raw value unnecessary | mask/minimize external | local |
| confidential, external unauthorized, raw value required | local | ask/deny |
| purpose disallowed | deny | ask |

`MCP`는 transport/interface이며 trust class가 아니다. `local`은 recipient metadata가 아니라 selected route다. 정책 의미와 허용 action은 `policy.md`에 versioned profile로 고정한다.

### 3.3 범위 밖

- 장기 대화에서 누적되는 조각 공개의 privacy accounting
- 암호학적 정보 흐름 보장
- 모델 provider가 실제로 데이터를 보존하는지에 대한 감사
- 이미지·음성·파일 내부의 multimodal 탐지
- 학습 데이터 memorization 또는 model inversion
- tool execution 이후의 사후 유출 통제

이 범위를 추가하면 최근 RootGuard, Dependency-Aware Privacy, ToolPrivacyBench와 별도 연구 문제가 되므로 본 논문에는 넣지 않는다.

## 4. 연구 공백

### 4.1 최근 선행연구와의 관계

| Work | 이미 해결한 부분 | 본 연구가 반복하지 않을 부분 | 남는 공백 |
|---|---|---|---|
| PAPILLON (2024) | local/cloud privacy delegation | 로컬-클라우드 분기 자체 | 조직·연구 기밀의 상태 변화와 exact-span routing 평가 |
| PRISM-style routing (2025) | semantic modulation 기반 cloud-edge routing | privacy-aware routing 개념 | 언어·도메인별 반사실 민감도와 action 오류 분해 |
| AgentSCOPE (2026) | agent pipeline privacy-flow benchmark | 일반적인 agent privacy taxonomy | egress span·status·recipient·necessity의 controlled intervention |
| Need to Know (2026) | task-essential/non-essential spans, query rewriting | 최소 필요 disclosure 개념 | rewrite가 아닌 allow/mask/local/ask action, 조직·연구 lifecycle secrecy, EN/KO |
| REDACT (2026) | multilingual PII detection/redaction | PII benchmark 재구축 | 비-PII 기밀과 lifecycle-dependent secrecy |
| RedactionBench (2026) | contextual PII, character-level metric | contextual PII만으로 novelty 주장 | same-span intervention과 routing/utility 결합 |
| PrivacyAlign (2026) | 인간의 맥락적 privacy judgment | contextual privacy가 중요하다는 주장 | 조직 정책이 명시된 실행 가능한 egress control benchmark |
| ToolPrivacyBench (2026) | recipient/purpose-bound private atoms in tools | tool recipient/purpose semantics | 공개 상태 전환, 조직·연구 기밀, exact span과 local/cloud action |
| RootGuard / Dependency-Aware Privacy (2026) | multi-turn cumulative disclosure | 누적 공개 문제 | 단일 후보 egress에서의 factorized controlled-intervention evaluation |

### 4.2 차별점

차별점은 넓은 “context-aware privacy”가 아니다. 다음 네 요소의 결합이다.

1. **비-PII 중심:** 제품 출시 전 기능, 미공개 실험 결과, 특허 전 아이디어, 내부 원가·협상 전략, source-code secret 등.
2. **lifecycle intervention:** 같은 span을 `draft → released`, `under NDA → public`, `internal → approved external`로 바꾼 최소쌍.
3. **policy-coupled evaluation:** 사실 label과 `P_0`가 산출한 `allow / mask / approved-external / local / ask / deny` compliance를 함께 측정.
4. **EN/KO paired evaluation:** 번역 정확도 경쟁이 아니라 동일 scenario semantics에서 언어에 따른 오류 차이를 측정.

이 중 하나라도 빠지면 최신 benchmark와의 차별성이 약해진다.

## 5. 연구 질문과 사전 등록 주장

### RQ1. 맥락 민감도

동일 span의 공개 상태·수신자 승인·목적 승인이 통제된 조건에서 바뀔 때 모델이 올바른 방향으로 판단을 바꾸는가?

**Primary claim C1:** 사전에 고정한 safe-input FPR에서 맥락 기반 방법은 primary fixed-taxonomy same-backbone baseline보다 비-PII 조직·연구 기밀 recall이 높다.

- Superiority criterion: 95% scenario-cluster bootstrap CI의 lower bound가 0보다 큼.
- Practical-relevance target: point estimate가 +10 percentage points 이상.
- 10pp는 pilot power analysis 전에 정한 목표이며, “최소 10pp 보장”으로 쓰지 않는다.
- primary method, comparator, backbone, FPR operating point, safe-case 정의는 hidden test 전에 하나씩 고정한다.

### RQ2. span과 policy compliance의 결합

어떤 component의 오류가 최종 action 오류로 연결되는가?

**Claim C2:** 사실 label과 policy-derived action을 함께 제공하면 $P_0$ 아래에서 boundary, disclosure, authorization, necessity, policy 오류를 조건부로 진단할 수 있다.

Oracle substitution 결과는 **conditional improvement**이며 독립적 causal contribution으로 더하지 않는다.

- missed-sensitive → external leakage
- false-sensitive → 불필요한 mask/local/ask
- authorization error → 잘못된 recipient route
- necessity error → task failure 또는 과도한 local routing
- boundary/atom error → literal 또는 semantic leakage

### RQ3. end-to-end confidentiality–utility trade-off

보호가 강한 privacy-aware baseline보다 unauthorized exposure를 줄이면서 task success를 유지하는가?

**Claim C3:** (a) transformation-only 비교에서는 같은 downstream model/route에서 masking 또는 rewriting의 효과를 측정하고, (b) full-system 비교에서는 route/model 변경을 시스템 비용에 포함한다. Primary 판정은 strong contextual baseline 대비 leakage superiority와 task-success 5pp non-inferiority를 모두 통과하는 intersection–union criterion이다. 5pp margin은 pilot 결과가 아니라 사용 허용 기준으로 사전 정당화한다.

### RQ4. EN/KO robustness

의미가 대응되는 EN/KO scenario에서 shared deployment threshold의 action과 leakage 격차가 어느 정도인가?

**Claim C4:** 번역본과 독립 작성본을 분리하고, paired scenario gap과 사전 정의한 subgroup 성능을 공개한다. EN/KO 동등성을 결과 전에 주장하지 않는다.

### RQ5. abstention

불확실 사례를 `ask user`로 보내는 것이 residual high-risk error와 사용자 부담에 어떤 trade-off를 만드는가?

**Claim C5:** calibrated deferral이 위험을 낮추는지 검증한다. 단조 감소를 가정하지 않으며 risk–coverage, excess risk over random rejection, ask rate, 추가 turn/latency, 최종 task completion을 함께 보고한다.

## 6. Benchmark 설계

### 6.1 목표 규모

최종 크기는 pilot power analysis로 확정한다. 초기 hierarchy와 planning envelope:

- 최소 400개 **semantic scenario**
- scenario당 평균 3개 controlled intervention variants
- 각 variant의 EN/KO language realization
- 약 2,400개 paired controlled items
- 200–400개 independently authored naturalistic/adversarial items
- 총 약 2,600–2,800개 items

Identifier hierarchy는 `semantic_scenario_id → intervention_variant_id → language_realization_id → paraphrase_id → workflow_execution_id → repetition_id`로 고정한다. 통계 cluster는 최상위 semantic scenario다.

### 6.2 통제 요인

1. **Disclosure status**
   - unreleased ↔ publicly released
   - patent-pending/internal draft ↔ published
2. **Recipient authorization**
   - approved enterprise endpoint ↔ unapproved public endpoint
3. **Purpose authorization**
   - policy-approved use ↔ prohibited unrelated use
4. **Raw-value necessity**
   - exact value required ↔ placeholder sufficient ↔ irrelevant

한 group에서는 가능하면 한 semantic factor만 바꾸고, 나머지 교호작용은 별도 group으로 표시한다. 독립 검토자가 의도한 factor를 모른 채 “정확히 한 요인만 바뀌었는가”를 확인한다. 각 intervention에는 여러 lexical realization, explicit/implicit cue strata, wording은 바뀌지만 policy state는 유지되는 invariant control을 둔다. 이는 실제 배포의 인과효과가 아니라 **controlled intervention sensitivity**를 측정한다.

### 6.3 정보 family

| Family | 예시 | 기존 PII benchmark와 다른 이유 |
|---|---|---|
| Personal | 연락처, 계정, 건강·재정 정보 | 비교 기준 및 일반성 확인 |
| Organizational | 내부 원가, 미공개 제품명, 협상 하한, 고객 계약 조건 | 문자열 유형이 아니라 조직 상태·수신자가 핵심 |
| Research | 미공개 실험 결과, 특허 전 아이디어, review 전 failure mode | publication lifecycle에 따라 민감도가 변함 |
| Credential/security | API key, private URL, system secret | 대부분 문맥과 무관하게 high-risk인 anchor category |

### 6.4 난이도 축

- explicit vs implicit confidentiality cue
- same-turn vs prior-turn cue
- single span vs dispersed spans
- exact entity vs derived value
- direct text vs tool argument
- benign technical term vs genuinely confidential technical term
- Korean particles/spacing and English morphology
- code-mixed EN/KO
- prompt injection that asks extractor to ignore policy

### 6.5 데이터 출처와 안전

- 실제 secret, 주민등록번호, phone number, API key는 사용하지 않는다.
- synthetic but structurally valid values를 사용한다.
- public disclosure text는 출처와 공개 시점을 기록하되, 이전 confidential state는 scenario로 재작성한다.
- organic Hermes 로그 46건은 metadata-only이므로 **workload frequency와 latency 분포 참고**에만 사용한다. benchmark 정답이나 prompt 내용으로 재구성하지 않는다.
- 사람 작성 사례는 동의서와 release license를 확보한다.
- domain expert가 realism과 policy plausibility를 평가하고, template author를 hold out한 subset과 consented·sanitized workflow description을 포함한다. 실제 payload error가 없으므로 ecological validity는 limitation으로 남긴다.

### 6.6 split

- semantic scenario 단위 60/20/20 split을 기본값으로 두고 pilot power analysis 후 확정
- 모든 variant, language realization, entity value, template, paraphrase chain을 같은 split에 묶음
- 별도 calibration partition 또는 nested dev procedure를 사용
- test payload, prompt, threshold, model, evaluator hash를 고정
- hidden test의 preregistered condition별 실행만 허용하며 결과를 본 뒤 수정하면 새 benchmark version을 만든다

### 6.7 annotation

1. 작성자가 관찰 가능한 context와 gold-only policy metadata를 분리해 작성한다.
2. 두 annotator가 독립적으로 exact span, disclosure state, recipient/purpose authorization, raw-value necessity, information atoms를 annotation한다.
3. Frozen $P_0$가 canonical/acceptable actions를 자동 산출한다. Annotator action은 policy validation용으로만 별도 수집한다.
4. 불일치는 제3 adjudicator가 해결하고 unknown/ambiguous를 강제 binary로 바꾸지 않는다.
5. organizational/research subset은 domain-aware adjudication을 거친다.
6. bilingual reviewer가 의미 동등성, 자연스러움, Korean particle/affix boundary를 검토한다.

Agreement는 pilot 전에 Gwet’s AC1을 primary로 고정하고, label prevalence와 95% CI를 함께 보고한다. Span은 pairwise character F1과 exact-match agreement를 사용한다. Ambiguity/adjudication rate와 classwise disagreement 원인을 공개한다.

## 7. Reference System: Privacy Router

Privacy Router의 관찰 가능한 동작만 기술한다.

1. OpenAI-compatible API 또는 MCP entry point가 egress payload를 받는다.
2. contextual extractor가 exact spans, dynamic categories, confidence, `is_essential`을 생성한다.
3. deterministic judge가 policy action을 선택한다.
4. non-essential sensitive span은 typed placeholder로 mask한다.
5. essential sensitive payload는 local model로 routing하거나 policy가 불명확하면 사용자에게 묻는다.
6. 외부 응답의 placeholder를 검증한 뒤 원문을 hydration한다.

Dynamic category generation과 ordered contextual questions는 **structured prompting**의 구현 선택이다. 새 privacy primitive로 명명하거나 주장하지 않는다.

### 7.1 시스템 관련 검증 대상

- exact span boundary
- overlapping/nested span policy
- adversarial placeholder collision/injection tests와 zero-observed-failure upper confidence bound
- hydration exactness와 source-to-serialized-byte mapping
- stream에서 metadata-before-content 보장
- tool argument inspection
- malformed model output의 fail-closed 처리
- model/provider 설정에 따른 latency와 cost

## 8. 비교 대상

### Core baselines

1. **Rules + PII NER:** regex, Microsoft Presidio, 공개 PII NER 중 재현 가능한 강한 모델.
2. **Fixed-taxonomy LLM:** 같은 backbone과 token budget, dynamic category와 contextual question 없이 고정 label로 extraction.
3. **Context-aware rewriting/control:** 공개 code가 있는 PAPILLON, Need to Know 또는 가장 가까운 재현 가능한 방법. Action이 다르면 literal characters뿐 아니라 proposition-level information atoms, derived leakage, recipient authorization, task utility로 공통 평가.
4. **Frontier direct classifier:** 최신 상용 LLM에 같은 schema를 주되 Privacy Router prompt decomposition 없이 direct prediction.

### Bounds

- unprotected external: privacy lower bound, utility upper reference
- mask-all-sensitive: leakage에 유리하지만 utility가 낮은 conservative bound
- local-only: 명시한 external-provider 경계에서 전송 0인 bound; endpoint 내부·side-channel 안전을 보장하지 않음

공개 code나 정확한 prompt가 없는 방법은 “reimplementation”으로 표시하고 원 논문 결과와 직접 수치 비교하지 않는다.

## 9. 평가 개요

### Detection

- contextual disclosure/authorization macro-F1 and per-family recall
- preregistered dev threshold에서 achieved test safe-FPR와 recall
- exact span and source-aligned character precision/recall/F1
- information-atom retention/leakage
- raw-value necessity macro-F1, conditioned on gold-sensitive spans
- $P_0$ compliance, acceptable-action accuracy, severity-weighted confusion
- controlled-intervention flip accuracy and invariance accuracy
- calibration curves, Brier score, AURC and risk–coverage curve

### End-to-end

- exact-secret byte leakage
- source-aligned literal span leakage
- proposition/information-atom leakage
- derived-value leakage
- unauthorized-recipient exposure
- task success / task score, conditional on selected route
- mask/local/ask/deny rates and completed outcome after ask
- hydration exactness, placeholder integrity, placeholder metadata leakage
- gateway/detector/provider/generation/user-wait latency decomposition
- tokens, cost per 1,000 requests, local peak memory; energy는 신뢰 가능한 계측 때만 보고

### Statistical protocol

- semantic scenario를 resampling unit으로 한 paired cluster bootstrap/permutation
- clustered variants에 ordinary McNemar exact test를 적용하지 않음
- family/language/difficulty 효과에는 mixed-effects model 또는 GEE
- multiple comparisons는 Holm correction
- 모든 CI는 95%; stochastic repetitions은 독립 benchmark sample로 세지 않음

## 10. 기대 결과가 아니라 판정 규칙

| 결과 | 허용되는 결론 |
|---|---|
| C1과 C3 모두 통과 | contextual control이 비-PII recall과 end-to-end privacy–utility를 개선 |
| C1 통과, C3 실패 | detector는 개선되지만 routing/masking이 utility 또는 leakage로 연결되지 않음 |
| C1 실패, action만 개선 | prompt novelty가 아니라 deterministic policy/system engineering 기여로 축소 |
| EN/KO gap 큼 | multilingual robustness 실패를 핵심 finding으로 보고 |
| frontier만 우수 | on-device/local claim 제거, benchmark paper로 전환 |
| baseline과 동률 | benchmark와 negative result만 제출 가능한지 재평가 |

결과가 나오기 전 “state of the art”, “privacy guarantee”, “language-agnostic”, “on-device superiority”를 쓰지 않는다.

## 11. 현실적인 venue 전략

### Primary

## 13. 연구 중단 조건

다음 중 하나가 발생하면 full benchmark 구축 전에 방향을 수정한다.

1. full-text artifact audit에서 lifecycle-status/authorization 최소쌍과 organizational/research atoms를 이미 충분히 제공하는 benchmark가 확인됨.
2. 80–120 item pilot에서 primary factual-label agreement가 0.67 미만이고 policy clarification 후에도 개선되지 않음.
3. context-aware method가 primary contextual baseline 대비 비-PII matched-FPR recall을 5pp도 개선하지 못함.
4. downstream task를 객관적으로 채점할 workflow를 최소 3개 domain에서 만들지 못함.
5. domain expert realism 검증 또는 independently authored holdout에서 authored-template artifact가 지배적임.

## 14. 최종 연구 명제

**Korean:** 조직·연구 기밀의 LLM-agent 전송 위험은 문자열 유형만으로 결정되지 않는다. 공개 상태, 수신자 승인, 목적 승인, 원문 필요성을 분리한 controlled-intervention 평가는 exact-span 탐지와 frozen-policy compliance, 실제 전송 leakage를 구분해 측정할 수 있게 한다.

**English:** Confidential-data risk at an LLM-agent egress decision is not determined by string type alone. Controlled interventions that separate disclosure state, recipient authorization, purpose authorization, and raw-value necessity enable distinct measurement of exact-span detection, frozen-policy compliance, and transmitted information leakage.
