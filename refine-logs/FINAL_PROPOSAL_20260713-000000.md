# Research Proposal: Cumulative Disclosure Benchmark

## Closed-Loop Evaluation of Recipient-Bound Cumulative Disclosure in Tool-Using LLM Agents

**Project context:** Future research direction extending Privacy Router
**Primary contribution:** Benchmark and empirical failure study
**Secondary contribution:** A stateful disclosure controller for comparisons and ablations
**Date:** 2026-07-13

---

# 한국어 제안서

## 1. 한 문장 연구 방향

**CumulativeCI-Agent는 LLM 에이전트가 여러 턴과 여러 외부 경로를 거치며 민감한 사실의 조각을 누적 노출하는 현상을, 수신자·목적별 허용 정책과 최종 과업 성공도를 함께 고려하여 측정하는 closed-loop benchmark이다.**

Privacy Router의 다음 연구는 단순히 “민감정보를 더 잘 찾는 분류기”를 만드는 방향보다, 다음 질문을 답하는 방향이 더 방어 가능하고 연구 가치가 높다.

> 개별 요청은 안전해 보여도, 여러 요청과 도구 호출을 합치면 하나의 민감한 사실이 완성될 수 있다. 현재의 deployable privacy defense는 이러한 누적 노출을 얼마나 놓치며, 이를 막으면서 실제 에이전트 과업 성공도를 얼마나 보존할 수 있는가?

이 제안에서 **benchmark와 evaluation methodology가 주 기여**다. 상태 기반 공개 제어기는 benchmark의 가설을 검증하고 ablation을 수행하기 위한 reference controller다. 이를 새로운 일반 보안 원리, 완전한 reference monitor, 형식적 noninterference 보장, 또는 보편적으로 새로운 privacy mechanism으로 주장하지 않는다.

## 2. 왜 기존 Privacy Router의 단순 확장으로는 부족한가

현재 Privacy Router의 강점은 명확하다.

1. OpenAI-compatible API와 MCP 경계에서 agent-generated prompt를 가로챈다.
2. 정규식으로만 찾기 어려운 개인·기업·연구 맥락의 민감정보를 Socratic reasoning으로 추출한다.
3. 각 span에 `is_sensitive`, `is_essential`, 동적 `SCREAMING_SNAKE_CASE` category를 부여한다.
4. 선택적 masking, local routing, user decision, blocking을 수행한다.
5. masking contract와 session cache를 사용하여 placeholder를 안전하게 관리한다.

하지만 연구 문제로 보면 다음 한계가 남아 있다.

### 2.1 판단 단위가 주로 현재 요청이다

현재 요청에 “TSMC 3nm 공정 수율은 15%다”가 한 번에 포함되면 탐지하기 쉽다. 그러나 다음과 같이 분산되면 각 요청은 독립적으로 덜 민감해 보일 수 있다.

- Event 1: “대상 회사는 TSMC야.”
- Event 2: “공정 노드는 3nm야.”
- Event 3: “내부 실험에서 수율이 15%였어.”
- Event 4: “이 세 정보를 외부 분석 도구의 보고서에 합쳐 줘.”

민감성은 각 문자열의 형식보다 **조합된 사실과 흐름**에 의해 발생한다.

### 2.2 같은 정보라도 수신자와 목적에 따라 허용 여부가 달라진다

“환자 이름”은 로컬 병원 기록 시스템에는 필요할 수 있지만, 외부 요약 모델에는 불필요할 수 있다. “논문 아이디어”는 연구팀 내부 memory에는 허용되지만, 일반 검색 도구에는 허용되지 않을 수 있다. 따라서 privacy 판단은 단순한 `sensitive/non-sensitive` 분류가 아니라 다음 tuple의 정책 판단이어야 한다.

- 누가 보내는가(sender)
- 누가 받는가(recipient)
- 어떤 목적인가(purpose)
- 어떤 동작인가(action)
- 어떤 field인가(field)
- 어떤 trust zone인가
- 어떤 사실이 이미 같은 수신자에게 공개되었는가(history)

### 2.3 masking이 항상 최선은 아니다

민감정보가 과업에 불필요하면 masking이 적절하다. 그러나 exact secret이 외부 도구의 입력으로 꼭 필요하다면 placeholder는 과업을 깨뜨릴 수 있다. 이 경우 선택지는 다음처럼 달라져야 한다.

- raw allow: 해당 수신자와 목적에 명시적으로 허용
- selective mask: 민감하지만 과업에 불필요
- local-only: 민감하고 과업에 필요하지만 외부 공개는 불허
- ask-user: 정책 또는 목적이 모호함
- block: 허용되지 않고 안전한 대안도 없음

따라서 다음 연구는 “민감정보 탐지 정확도” 하나가 아니라 **privacy–utility trade-off를 실제 과업 실행으로 평가**해야 한다.

## 3. 패턴 기반 정보와 맥락 기반 정보의 구분

### 3.1 Pattern-defined identifiers

구문 또는 형식이 식별에 큰 도움을 주는 정보다.

- 주민등록번호
- 전화번호
- 이메일 주소
- 신용카드 번호
- 여권번호
- 계좌번호
- API key와 credential token

이들은 regex, checksum, dictionary, NER, structured parser가 강한 영역이다. Privacy Router는 이러한 detector를 버릴 필요가 없다. 오히려 deterministic detector는 높은 precision과 낮은 비용을 제공하는 1차 signal로 유지해야 한다.

### 3.2 Context-dependent confidential facts

문자열 형식만으로는 민감성을 결정하기 어려운 정보다.

- “내부 3nm 공정의 수율은 15%다.”
- “다음 분기 가격 인상률은 12%다.”
- “아직 공개하지 않은 RAG failure recovery 방법은 X다.”
- “환자가 특정 질환으로 진단되었다.”
- “이 사람이 다음 인사 이동 대상이다.”

이 영역에서는 문자열 자체보다 **사실의 주체, 관계, 공개 상태, 수신자, 목적, 과업 필요성, 이전 대화**가 중요하다. 본 연구는 pattern detector와 contextual estimator를 경쟁시키지 않는다. 다음의 hybrid 구조를 평가한다.

1. deterministic detector가 명확한 structured identifier를 찾는다.
2. semantic extractor가 format-free confidential fact와 fragment를 찾는다.
3. policy layer가 recipient-purpose authorization을 결정한다.
4. cumulative state가 여러 event의 fragment가 하나의 사실을 완성하는지 평가한다.
5. task executability signal이 masking/local/ask/block 중 어떤 조치가 과업을 보존하는지 추정한다.

## 4. 핵심 연구 공백 가설

관련 연구는 이미 여러 축을 각각 다룬다.

- **DelegateCI-Bench / Need to Know**: 과업 수행에 필요한 정보만 cloud LLM에 전달하는 contextual-integrity 기반 query rewriting
- **ToolPrivacyBench**: 도구 사용 에이전트에서 목적에 맞는 정보 전달 여부 평가
- **AgentLeak**: multi-agent system의 내부 channel privacy leakage
- **Silent Egress**: 여러 outbound request로 secret을 분할하는 shared exfiltration
- **RTBAS / PrivacyChecker / Contextualized Defense**: tool-call 또는 runtime 경계의 privacy/security control
- **PAPILLON/PUPA**: local proxy와 cloud model을 조합한 privacy-preserving delegation
- **PRISM**: entity-level sensitivity에 따른 cloud/edge/collaborative routing

따라서 “context-aware privacy routing”이나 “task-essential masking” 자체는 충분한 신규성 주장이 아니다. 제안하는 공백은 다음 네 요소의 **교차점**이다.

1. closed-loop agent task
2. cloud/tool/inter-agent/memory 등 heterogeneous egress
3. recipient-purpose별 authorization
4. 여러 event의 semantic fragment를 합친 cumulative disclosure와 최종 task utility의 공동 평가

이 공백은 아직 검증된 사실이 아니라 **prior-art kill gate로 먼저 검증할 가설**이다.

## 5. 연구 질문

### RQ1. 누적 노출 실패 규모

Deployable per-event privacy defense는 동일한 task success 조건에서 recipient-bound cumulative disclosure를 얼마나 놓치는가?

### RQ2. 상태 표현의 효과

각 방법이 disjoint calibration set에서 동일한 사전 정의 benign FPR operating point를 목표로 개별 threshold를 고정했을 때, recipient-purpose-partitioned semantic history가 per-event history와 full-prefix history보다 split/paraphrased leak를 더 잘 탐지하는가?

### RQ3. 조치의 privacy–utility 비용

`allow`, `selective_mask`, `local_only`, `ask_user`, `block`은 task success, latency, compute cost, API cost, 사용자 개입 횟수에 어떤 trade-off를 만든다?

### RQ4. 실패 조건

언어 변화, paraphrase, contradiction, temporal update, alias, recipient switch, purpose switch, prompt injection, state corruption, timeout에서 어떤 failure mode가 발생하는가?

## 6. 핵심 개념과 형식화

### 6.1 Egress event

시간 `t`의 egress event를 다음처럼 정의한다.

\[
e_t = (s_t, r_t, p_t, a_t, f_t, z_t, x_t)
\]

- `s_t`: sender 또는 agent identity
- `r_t`: canonical recipient identity/class
- `p_t`: declared purpose
- `a_t`: action 또는 operation
- `f_t`: destination field/schema
- `z_t`: trust zone와 sink type
- `x_t`: 실제로 외부 경계를 통과하려는 payload

### 6.2 Protected fact와 fragment

Extractor는 payload를 단순 category 목록이 아니라 semantic fact/fragment 집합으로 변환한다.

\[
F(x_t) = \{q_{t,1}, q_{t,2}, \ldots\}
\]

예를 들어 `TSMC`, `3nm`, `15%`, `internal yield`는 서로 다른 fragment지만, history와 결합하면 하나의 protected fact를 entail할 수 있다.

### 6.3 Recipient-purpose-partitioned enforcement history

\[
H_{r,p}^{(t)} = \text{facts already released or irrevocably reserved for recipient } r \text{ under purpose } p
\]

Raw transcript 전체를 그대로 저장하는 것이 아니라, 평가 대상 fact와 provenance를 최소한으로 기록한다. 외부 전송이 시작될 수 있는 시점부터 해당 fact는 conservative reservation으로 history에 남긴다. 전송 acknowledgement 실패를 이유로 reservation을 제거하지 않는다. confirmed delivery는 별도 audit evidence다.

### 6.4 Unauthorized first disclosure

정책 `P`가 recipient-purpose-action-field별 허용 fact를 정의한다고 하자.

\[
Leak(e_t)=1
\]

은 다음이 모두 참일 때다.

1. `H_{r,p}^{(t-1)} \cup F(x_t)`가 protected fact `q`를 의미적으로 완성한다.
2. `P(r,p,a,f,q)=deny`다.
3. 해당 recipient-purpose tuple에 `q`가 이전에 unauthorized cleartext로 공개되지 않았다.
4. controller가 release 전에 차단·localize·질의하지 못했다.

동일한 사실의 반복 출력이 leak count를 무한히 늘리지 않도록 **first disclosure**를 기본 단위로 사용한다.

### 6.5 최적화 관점

본 연구는 privacy와 utility를 임의의 하나의 점수로 곱하지 않는다. 더 명확한 constrained objective를 사용한다.

\[
\min \; \Pr[\text{unauthorized first disclosure}]
\]

subject to

\[
TaskSuccess_{method} \ge TaskSuccess_{baseline} - \epsilon.
\]

제안서 수준의 non-inferiority margin은 `ε = 5 percentage points`다. 실제 confirmatory value와 power는 discarded pilot 후 preregistration에서 동결한다.

## 7. 누적 공개 벤치마크 설계

### 7.1 도메인

최소 네 영역을 사용한다.

1. **Personal administration**: identity, contact, finance, forms
2. **Enterprise operations**: strategy, pricing, manufacturing, HR
3. **Research workflow**: unpublished concepts, results, review, patent timeline
4. **Healthcare**: diagnosis, treatment, appointment, clinical summary

각 도메인은 pattern-defined identifier와 context-dependent confidential fact를 모두 포함한다.

### 7.2 지원 egress

- external/cloud LLM request
- external tool call argument
- inter-agent 또는 MCP message
- memory write
- artifact/document write
- trusted local UI output

하나의 task는 4–8개의 egress event를 갖도록 설계하되, highest shared template/scenario family를 split 및 inference의 cluster 단위로 사용한다.

### 7.3 누적 공격/실패 패턴

1. **Split disclosure**: 하나의 fact를 여러 event로 분리
2. **Paraphrase accumulation**: 동일 fact를 다른 표현으로 반복
3. **Alias linking**: 이름, 직책, pronoun, project codename 연결
4. **Recipient switch**: 내부 recipient에는 허용되지만 외부 recipient에는 불허
5. **Purpose switch**: scheduling 목적에서 수집한 정보를 marketing/research 목적으로 재사용
6. **Temporal update**: 과거 fact가 수정·취소·만료됨
7. **Contradiction**: 새 정보가 이전 정보와 충돌
8. **Prompt-injected egress**: tool/web content가 leak를 유도
9. **Cross-channel composition**: cloud request와 tool call이 함께 fact를 완성
10. **Benign authorized repetition**: 누적되어도 정책상 허용되는 hard negative

### 7.4 Benign twin

모든 attack-bearing scenario는 가능한 경우 benign twin을 갖는다.

- 같은 정보지만 authorized recipient
- 같은 recipient지만 legitimate purpose
- 공개된 정보
- semantically similar하지만 다른 subject
- 필요한 최소 정보만 전달

이 구조는 detector가 단지 “민감해 보이는 단어가 많다”는 이유로 차단하는 것을 방지한다.

### 7.5 Annotation schema

각 case에는 최소 다음 annotation이 필요하다.

- `task_id`, `scenario_family_id`, `event_id`
- `fact_id`, `fragment_id`, alias set
- canonical recipient identity/class
- purpose, action, field, trust zone
- authorization decision과 contract version
- event별 disclosure attempt
- cumulative entailment completion point
- expected safe action
- task-success rubric
- benign/attack-bearing label
- language와 domain

Test split의 policy, authorization, fact aliases/fragments, final task-success rubric는 독립적인 두 annotator가 blind하게 작성하고 disagreement를 adjudication한다.

### 7.6 Split 규칙

- 동일 template/scenario family는 한 split에만 존재한다.
- entity, source document, workflow skeleton, attack pattern overlap을 검사한다.
- train/dev/calibration/test를 분리한다.
- calibration set은 RQ2의 matched-FPR threshold만 선택한다.
- test label은 model, prompt, threshold, baseline, retry/failure rule이 동결되기 전에는 열지 않는다.

## 8. Reference controller: 상태 기반 공개 제어기

### 8.1 역할

TEDC는 benchmark를 검증하기 위한 cooperative middleware다. 지원 adapter를 통하지 않고 직접 network를 호출하는 악성 agent, malicious OS/admin, covert channel, image/audio exfiltration, recipient class 간 collusion은 범위 밖이다.

### 8.2 처리 흐름

```text
Agent action
  -> Egress adapter
  -> Recipient/purpose canonicalization
  -> Pattern + semantic fact extraction
  -> Contract authorization lookup
  -> Recipient-purpose cumulative-state check
  -> Task-executability estimation
  -> Deterministic action precedence
  -> allow | selective_mask | local_only | ask_user | block
  -> state reservation/update
  -> supported sink
```

### 8.3 Contract

Contract는 hidden gold label에서 자동 생성하지 않는다. 관리자 또는 task/tool schema 작성자가 독립적으로 정의한다.

```text
(recipient, purpose, action, field, trust_zone, fact_class) -> allow/deny
```

Primary experiment에는 correct-but-deployable contract를 제공하고, incomplete/conflicting/stale contract는 별도 robustness study로 평가한다.

### 8.4 Task executability

하나의 모호한 `is_essential` boolean만 사용하지 않고 세 수준을 분리해 보고한다.

1. **Schema validity**: masking 후 request가 schema를 만족하는가
2. **Sandboxed step success**: deterministic mock tool이 rollback 가능한 환경에서 성공하는가
3. **Final task success**: 전체 closed-loop task가 최종 목적을 달성하는가

Estimator가 실패하거나 contract/recipient가 불명확하면 external release를 낙관적으로 허용하지 않는다. `local_only`, `ask_user`, `block` 중 deterministic fail-closed precedence를 따른다.

### 8.5 Placeholder와 hydration

외부 recipient에게 보내는 placeholder는 민감한 cleartext를 포함하지 않는다. **외부 cleartext hydration은 연구 범위에서 제거한다.** Placeholder 복원은 originating user에게 보여 주는 trusted local UI 내부에서만 허용한다. 외부 도구, cloud model, peer agent가 exact secret을 필요로 하면 그 action은 local-only로 실행하거나 새로운 explicit authorization event를 거쳐야 한다.

이는 hydration을 별도의 우회 egress로 만드는 복잡성을 제거한다.

## 9. Baseline 설계

### 9.1 기본 정책 baseline

- no guard
- blanket masking
- frozen current Privacy Router

### 9.2 동일 verifier를 사용한 history ablation

- current event only
- previous event only
- full raw prefix
- exact fact ledger
- embedding ledger
- recipient-purpose semantic ledger

동일한 frozen verifier/model/prompt/threshold budget을 사용하여 history representation의 효과만 비교한다.

### 9.3 관련 시스템 baseline

공개 manuscript/code가 허용하는 범위에서 다음 계열을 재현한다.

- Contextual Integrity query rewriting / DelegateCI-style method
- purpose-bound policy checker
- RTBAS/PrivacyChecker/Contextualized Defense 계열
- PRISM entity-sensitive routing
- PAPILLON/PUPA local-cloud delegation

재현이 불완전하면 차이를 명시하고, 해당 비교로 superiority claim을 하지 않는다.

### 9.4 공정한 비교

두 regime을 모두 보고한다.

- **Capability-matched**: 같은 policy, model access, local verifier, state access
- **Cost-matched**: 같은 approximate token/API/latency budget

Policy-capable baseline에는 동일한 independently authored deployable contract를 제공한다. Gold annotation은 oracle upper bound에서만 사용한다.

## 10. 평가 지표와 confirmatory claim

### 10.1 Primary privacy metric

**Task-level Unauthorized First-Disclosure Incidence**

한 task에서 하나 이상의 protected fact가 unauthorized recipient-purpose tuple에 처음 공개되면 1, 아니면 0이다.

### 10.2 Cumulative detection metric

**Macro Task-Level Cumulative Leak Recall**

각 attack-bearing task에서 사전 annotation된 target fact 중, first unauthorized release 전에 안전 조치가 발동한 비율을 계산하고 task별 macro average를 사용한다. Method가 실제 disclosure를 시도했는지에 따라 denominator를 바꾸지 않는다.

### 10.3 Matched benign FPR

RQ2/C2는 **matched-FPR comparison**으로 고정한다.

- 각 method는 disjoint calibration set에서 자기 score distribution에 맞는 threshold를 개별 선택한다.
- 모든 method는 동일한 사전 정의 benign FPR target을 목표로 한다.
- threshold는 test 전에 동결한다.
- discrete score 때문에 정확히 맞출 수 없으면 target을 초과하지 않는 보수적 operating point와 실제 달성 FPR을 보고한다.
- test에서는 recall, task success, 실제 FPR을 모두 보고하며 threshold를 재조정하지 않는다.

### 10.4 Utility 및 비용

- final binary task success
- rubric-based partial success
- required-fact omission
- user interruption count
- action distribution
- cold/warm p50/p95 latency
- local compute와 external API cost

### 10.5 제안 confirmatory claims

**C1 — Closed-loop privacy–utility:** 가장 강한 deployable baseline보다 unauthorized first-disclosure incidence를 최소 5 percentage points 낮추면서, task success 손실의 simultaneous lower bound가 5 percentage points 이내다.

**C2 — Cumulative state representation:** 동일한 matched benign FPR에서 recipient-purpose semantic history가 같은 verifier의 per-event 및 full-prefix baseline보다 macro cumulative-leak recall을 최소 15 percentage points 높이고, 각 baseline 대비 task success 손실이 5 percentage points 이내다.

둘 중 하나의 bound라도 실패하면 해당 claim은 지원되지 않는다. Privacy improvement만으로 task failure를 정당화하지 않는다.

## 11. 통계 및 실험 실행 원칙

1. 기존 27개 single-turn case는 smoke test일 뿐 confirmatory evidence가 아니다.
2. discarded pilot로 generator, mixture, model, prompt, baselines, failure/retry rules, matched-FPR calibration, sample size를 동결한다.
3. highest shared template/scenario family를 bootstrap/resampling cluster로 사용한다.
4. API failure, timeout, malformed output, aborted task를 intention-to-treat로 남긴다. Method별로 실패 case를 재생성하거나 제외하지 않는다.
5. Paired absolute effects와 simultaneous confidence bounds를 사용한다.
6. Power가 부족하면 sample을 임의로 계속 추가하지 않고, 사전 정의된 grid와 stop rule에 따라 inconclusive로 보고한다.
7. Primary comparison은 deterministic mock tools와 하나의 frozen open/local agent에서 수행한다.
8. Stratified subset에서 proprietary API 결과를 추가 검증하되, record/replay는 semantic quality의 대체물이 아니라 diagnostic 도구로만 사용한다.

정확한 confidence procedure, FPR target/tolerance, discrete threshold tie rule, sample-size grid와 simulation code는 pilot 후 preregistration에 기록한다.

## 16. 실패 가능성과 해석

### 16.1 TEDC가 full-prefix보다 좋아지지 않을 수 있다

그 경우 recipient partition의 필요성이 약하다는 의미다. Negative result를 숨기지 않고 어떤 condition에서 full-prefix가 충분한지 보고한다.

### 16.2 semantic history가 false positive를 늘릴 수 있다

Matched-FPR 설계를 통해 threshold 차이로 recall이 좋아 보이는 착시를 제거한다. 동일 FPR에서도 이득이 없으면 C2는 실패다.

### 16.3 task utility가 크게 떨어질 수 있다

Privacy improvement가 있어도 non-inferiority bound를 통과하지 못하면 C1/C2를 지원하지 않는다. 이 경우 user confirmation이나 local execution이 필요한 workload class를 분석한다.

### 16.4 synthetic benchmark가 실제 agent를 대표하지 못할 수 있다

Deterministic harness는 internal validity를 위한 것이다. Proprietary subset과 privacy-preserving organic trace abstraction은 external validity를 보완하지만, 전체 현실을 대표한다고 주장하지 않는다.

### 16.5 prior art가 공백을 이미 채웠을 수 있다

이 경우 mechanism novelty를 억지로 유지하지 않는다. 재현성, benchmark coverage gap, failure analysis로 pivot한다.

## 17. 최종 thesis

> **Privacy Router의 가장 설득력 있는 다음 연구는 새로운 민감정보 category나 또 하나의 router를 제안하는 것이 아니다. 여러 agent egress가 recipient와 purpose별로 어떤 semantic fact를 누적 공개하는지 측정하고, 이를 막는 방법이 실제 task를 끝까지 수행하는지 검증하는 benchmark-first 연구다.**

이 framing은 현재 프로젝트의 강점—language-agnostic contextual extraction, selective masking, local/cloud routing, MCP/OpenAI-compatible boundary—을 보존한다. 동시에 DelegateCI-Bench, ToolPrivacyBench, AgentLeak, Silent Egress, RTBAS, PAPILLON, PRISM과 직접 충돌하는 과도한 mechanism novelty claim을 피한다.

# English Proposal

## 1. Thesis

**This closed-loop benchmark measures how semantically related fragments accumulate into unauthorized protected facts across multiple LLM-agent egresses, under recipient- and purpose-specific authorization, while also measuring final task success.**

The benchmark and evaluation methodology are the primary contributions. A cooperative stateful disclosure controller is used to test the benchmark and isolate causal factors. It is not presented as a new privacy principle, a complete reference monitor, a formal noninterference system, or a universally novel routing mechanism.

## 2. Problem

A single outbound message can appear harmless while several messages, tool calls, peer-agent messages, and memory writes jointly disclose a protected fact. The same fact may be authorized for one recipient and purpose but forbidden for another. A defense therefore needs evaluation beyond isolated PII detection:

- cross-event semantic accumulation;
- canonical recipient and purpose;
- heterogeneous cloud, tool, MCP, and storage sinks;
- deployable contracts rather than hidden gold policies;
- final closed-loop task success rather than proxy fluency.

The current Privacy Router provides a strong starting point—contextual extraction, `is_essential`, selective masking, local routing, user decisions, and fail-closed interception—but does not yet supply a benchmark for recipient-purpose-partitioned cumulative disclosure.

## 3. Research Questions

- **RQ1:** How much cumulative unauthorized disclosure do deployable per-event defenses miss at matched task success?
- **RQ2:** At a matched benign-FPR operating point, does recipient-purpose-partitioned semantic history outperform per-event and full-prefix histories on split and paraphrased leaks?
- **RQ3:** What privacy, utility, latency, monetary-cost, and interruption trade-offs arise from allow, masking, local-only, ask-user, and block actions?
- **RQ4:** Where do such controllers fail under language shift, aliases, contradiction, temporal updates, recipient/purpose changes, prompt injection, and state faults?

For RQ2, every method selects its own threshold exclusively on a disjoint calibration split to target the same predeclared benign FPR. Thresholds are frozen before test evaluation. If discrete scores cannot hit the target exactly, the conservative operating point at or below the target is used and the achieved FPR is reported.

## 4. Benchmark

The cumulative disclosure benchmark contains benign and attack-bearing closed-loop twins across personal administration, enterprise operations, research workflows, and healthcare. Tasks exercise cloud-model requests, tool arguments, inter-agent/MCP messages, memory writes, artifact writes, and trusted local output.

Attack-bearing tasks annotate protected facts whose fragments are distributed over at least two egress events and target at least one unauthorized recipient-purpose tuple. Patterns include split disclosure, paraphrase accumulation, alias linking, recipient and purpose switches, temporal updates, contradiction, prompt-injected egress, and cross-channel composition. Benign twins distinguish genuine policy violations from merely sensitive-looking language.

The highest shared template/scenario family is the split, resampling, and inference cluster. No family crosses train, development, calibration, and test. Test policies, event authorization, fact fragments/aliases, and task-success rubrics are independently double-annotated and adjudicated.

## 5. Stateful Disclosure Controller

The controller mediates only supported cooperative adapters. It canonicalizes recipient and purpose, extracts structured identifiers and semantic fact fragments, checks an independently authored contract, evaluates recipient-purpose-partitioned enforcement history, estimates task executability, and applies deterministic precedence among:

- raw allow;
- selective placeholder masking;
- local-only execution;
- non-revealing user clarification;
- block.

Missing contracts/identities, verifier failures, and state failures fail closed. External cleartext hydration is excluded. Placeholder restoration is permitted only inside the trusted local UI for the originating user. Exact secrets required by external tools/models/peers require local execution or a fresh explicit authorization event.

Policy authorization, fact reservation, and action selection are serialized at the recipient-purpose partition. Once an external send can occur, reserved facts remain conservatively represented in enforcement history even if acknowledgement fails. This is an empirical cooperative controller, not an end-to-end delivery guarantee.

## 6. Evaluation

Primary metrics are:

- task-level unauthorized protected-fact first-disclosure incidence;
- macro task-level cumulative leak recall at matched benign FPR;
- final binary and rubric task success;
- required-fact omission;
- action and user-interruption rates;
- cold/warm latency and total compute/API cost.

Baseline families include no guard, blanket masking, the frozen current Privacy Router, same-verifier per-event/full-prefix/exact-ledger/embedding-ledger methods, Contextual-Integrity rewriting, policy checkers, and faithfully reconstructable RTBAS/PRISM/PAPILLON-style systems. Capability-matched and cost-matched regimes are both reported. Gold policy and detector labels are oracle diagnostics only.

The provisional confirmatory claims are:

- **C1:** at least a 5-percentage-point absolute reduction in unauthorized first-disclosure incidence versus the strongest deployable baseline, with final task success non-inferior within 5 percentage points;
- **C2:** at least a 15-percentage-point macro cumulative-recall improvement over both same-verifier per-event and full-prefix baselines at matched benign FPR, with task success non-inferior within 5 percentage points against each.

A discarded pilot freezes the generator, mixture, candidate baselines, thresholds, retry/failure handling, sample size, and inference plan before test generation and label unlock. Existing 27-case data remains a smoke suite, not confirmatory evidence. Underpowered results are reported as inconclusive.

## 7. Novelty Discipline

The proposed gap is a hypothesis. Before implementation, two independent coders perform a source-quoted claim chart covering Contextual Integrity, DelegateCI-Bench, ToolPrivacyBench, AgentLeak, Silent Egress, RTBAS, PrivacyChecker/Contextualized Defense, PAPILLON/PUPA, PRISM, classical DLP/reference monitors/capabilities, and newly discovered related work.

The benchmark novelty claim is withdrawn if prior work already combines—or clearly discloses an obvious combination of—closed-loop heterogeneous sinks, recipient-purpose authorization, cumulative semantic fact leakage, and final task utility. If the gate triggers, the project pivots to transparent replication, coverage-gap analysis, and failure analysis. No unsupported “first,” “best,” or “state-of-the-art” claim is allowed.

## 8. Deliverables

1. Versioned benchmark schema and data card
2. Annotated dataset and validator
3. Deterministic closed-loop harness
4. Baseline adapters and fidelity report
5. Stateful disclosure controller reference implementation
6. Preregistration and power report
7. Results with confidence intervals and privacy–utility Pareto frontiers
8. Failure taxonomy and negative-results report
9. Source-quoted prior-art claim chart

## 9. Final Positioning

The strongest future direction for Privacy Router is not another sensitive-data taxonomy or generic router. It is a benchmark-first study of cumulative, recipient-bound agent disclosure with closed-loop utility. This preserves the project's practical strengths while avoiding inflated novelty claims in areas already occupied by query rewriting, purpose-bound tool privacy, local-cloud delegation, and runtime agent controls.
